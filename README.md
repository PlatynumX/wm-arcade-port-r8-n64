# WWF WrestleMania Arcade -> N64 source port (r9 source-engine pass)

**Primary target:** Nintendo 64 / libdragon.  
**Porting rule:** when the arcade source implements it, translate that implementation and use its original data/assets. Do not replace it with invented N64 behavior.

r9 is the first broad **shared-engine** pass. It is not a claim that the complete arcade game is already playable. The point of this revision is to replace one-off bring-up code with reusable source-driven systems that whole parts of the original program can execute on.

## What r9 actually translates

- **53 Hz arcade source clock.** `DISPLAY.EQU`'s source tick rate runs independently of 60 Hz N64 presentation, so translated sleeps, timers, processes and animation cadence are no longer accelerated to 60 Hz.
- **Cooperative source-process scheduler.** Shared CREATE/sleep/kill-by-PID behavior is used by translated frontend processes instead of hand-coded screen timers.
- **Packed BMOD records.** The original 64-bit background block records are decoded generically; CI extracts `NTITLESCBMOD` and `SPORTBKBMOD` directly from `BGNDTBL.ASM`.
- **Original BLIMP title artwork.** `BIGWWF.BDB`/`BIGWWF.BDD` are decoded into their 40 CI8 blocks and six RGB555 palettes, cross-validated against `NTITLESCBMOD`, and rendered from the original packed block records rather than a flattened WIMP crop.
- **Original title sparkle artwork/process lifetime.** All 69 WIMP frames named by `MISC.LOD` from `SPARKLE.IMG` are generated as source sprites. `show_title` creates/kills the source `FLASH_PID` and `ATTRACT_ANIMPID` processes alongside `cycle_lava`. The shared `SPRINKLE_GLINTS`/`RANDOM_SPARKLE` helper bodies and `WHERE_WRESTLMANIA_SPARKLES` table are absent from the checked-in WWF tree, so placement/random cadence is clearly marked provisional rather than source-exact.
- **Typed animation stream.** Mixed WORD/LONG operands are preserved. Implemented commands execute source operand widths and direction rules; unknown commands fail closed instead of being guessed.
- **Whole-source dependency IR.** CI scans every `SUBR`/`SUBRP`, static call/process edge and unresolved dynamic edge, with frontiers rooted at `attract_mode` and `start_match`.
- **Whole-source animation IR.** CI mechanically preserves typed WORD/LONG animation data and W/L packing macros across the historical ASM tree.
- **Source selection core from `SELECT.ASM`.** The 2x4 cursor grid, exact crouton coordinates, source BMOD placement, player start/mug/sound data, `scramble_table` roster mapping, attributes, legal four-way movement, START+UP random-selection gate, random wander/home rules, 15-second source selection timer and 30-tick final wait constants are translated in portable C.
- **Source-driven attract execution.** Initial 8-tick blank, active source routine order, DCS/Midway/title timing, Midway background movement, title lava scheduling, and the source title sparkle process lifetime remain source-driven.
- **Original artwork paths already proven on N64.** Midway Sports uses the original 17 WIMP pieces; title art is derived from original artist/BMOD data; Bret remains the first wrestler with the current visual backend.
- **`show_gameplay`'s attract-mode `start_match` creation path.** `ATTRACT.ASM::show_gameplay` is just `WRESTLE.ASM::start_match` run with `PSTATUS==0`; the `#0plyr` branch's `RNDRNG0(7)`-skip-7 wrestler draw, `LIFEBAR.ASM::init_life_data` (`LIFE_MAX`=163), and PLYRNUM/PSIDE wrestler-actor creation are translated (`wm/match.h`), on the real `SLEEP 3*60` + `wait_on_butn 10*TSEC` timing. See the boundary below for what this does not yet do.
- **Bret's live control layer and a real visual backend for it.** Whichever actor draws `WM_ROSTER_BRET` runs the actual `wm_arcade_move_bret` dispatcher every tick, not a harness. `wm/bret_backend.h` resolves `WM_BRET_ANIM_STAND2/4`/`TORSO2/4` and 7 of Bret's light/power punch/kick animation ids to their real `wm_visual_sequence` data and drives two `wm_visual_state` tracks (body + torso) from it -- the merge adapter `wm/arcade/wm_arcade_bret.h` itself calls for. Every other animation id, and every other wrestler, still resolves to nothing.
- **Real movement physics, and a real walk cycle to go with it.** `wm/movement.h` translates `WRESTLE.ASM::convert_facing` and `set_velocities` exactly (per-direction velocity table, `walk_fast`/opponent-ONGROUND-or-DEAD 1.5x boost, backward-facing 0.9x reduction) and wires `execute_walk`'s `MOVE_DIR`/`OBJ_CONTROL` (`M_FLIPH`) dispatch as Bret's real `execute_walk` callback. `wm/bret_backend.h` also now runs `change_walk_anim`'s leg-cycle half: all 12 `hrt_walkM_fF_anim` sequences `hrt_leg_anims_table` (`BRET.ASM:2897`) can select are extracted and wired, so a Bret actor with real input genuinely walks with the correct animation, not just a position change under a frozen sprite. `change_walk_anim`'s torso half (`hrt_torso_anims_table`, `BRET.ASM:2981`) is fully wired too, diagonal and all 12 off-diagonal turn-transition entries -- see the next bullet.
- **`FACING_DIR`/`NEW_FACING_DIR` are real state now, and turning genuinely animates.** `wm/arcade/wm_arcade_closest.h`'s `wm_arcade_update_newfacing` translates `WRESTLE.ASM:3018`'s `update_newfacing` (live `NEW_FACING_DIR` toward the opponent, every tick, for every actor -- wired into `wm_match_tick` unconditionally, exactly where `WRESTLE.ASM`'s own per-process main loop calls it), and `wm/movement.h`'s `wm_execute_walk` translates `set_rotate_anim`'s literal `FACING_DIR=NEW_FACING_DIR` catch-up for the `#zip`/stance case (`WRESTLE.ASM:5082-5083`). Just like the source, `FACING_DIR` stays frozen at its last idle value while actually walking -- `change_walk_anim`'s leg half never writes it -- so facing one way while walking another (e.g. after running past a repositioned opponent) is representable. Both actors also start the match with real position *and* facing from the same real `WRESTLE.ASM:2691-2755` `#set0` placement init (`wm/match.h`'s `place_wrestler`, `#teamX_starts` table: `RING_X_CENTER-85,1127+93,WM_MOVE_UP_RIGHT` for P1, `RING_X_CENTER+85,1103+93,WM_MOVE_DOWN_LEFT` for the opponent) instead of a zeroed default -- the two positions are chosen so each wrestler's real starting facing already points at the other's real starting position, so nothing spuriously turns on tick 1. `set_rotate_anim`'s own turn-animation *selection* for the `#zip`/idle-turn case is now wired too (`wm_bret_rotate_anim`, `hrt_rotate_anims_table`), and `change_walk_anim`'s torso half genuinely reaches and animates the off-diagonal (mid-turn) region of `hrt_torso_anims_table` while walking, using the real `hrt_N_to_M_turn2_anim` sequences -- each carrying one or two real `ANI_SETFACING` commands (`HRTSEQ1.ASM:460-524`) that `wm_bret_backend_tick` fires at their exact hand-traced frame, which is what actually promotes `FACING_DIR` while genuinely walking. `execute_walk`'s own INTURN freeze (`WRESTLE.ASM:5222-5252`) is wired too and load-bearing: without it the instant `FACING_DIR` catch-up would truncate every turn animation almost immediately. The leg turn anims' own `ANI_XFLIP` (4 of the 6 canonical bodies -- the two adjacent-quadrant ones never cross the sprite's own left/right mirror line) is wired too, toggling `OBJ_CONTROL`'s `M_FLIPH` at its real, hand-traced frame index, same mechanism as the torso's `ANI_SETFACING`. Diagonal entries still reduce to picking between `hrt_torso2_anim` and `hrt_torso4_anim` (`hrt_torso8_anim`/`hrt_torso6_anim` are literal `SUBR` aliases of those two in `HRTSEQ1.ASM`, not separate artwork, confirmed by extracting and diffing their frame data). Translating this also surfaced a real pre-existing gap: Bret's 6 attack animations lead with a real `MODE_UNINT` (`HRTSEQ2.ASM`) this port's simplified `change_anim` never propagated onto the actor, so an attack could get silently stomped by the new idle-turn reselection on the same tick -- `wm_bret_backend_change_anim`/`wm_bret_backend_tick` now set and clear it for real, matching the source.
- **A real, human-playable single-player match for Bret.** `WM_APP_MODE_MATCH_INIT` (after select/pregame) is no longer a dead end: `wm_match_start_selected` translates `start_match`'s PSTATUS!=0 `#1plyr` path using whatever the select screen actually chose, and `wm/human_input.h` maps real controller state onto the same `but_val_cur`/`stick_val_cur` fields `DRONE.ASM`'s commit path writes for CPU wrestlers, so a human playing Bret drives the real `wm_arcade_move_bret` dispatch, real movement and walk animation, and the real visual backend above with actual button/stick presses.
- **Real attack-box activation for Bret's 6 wired attacks** (now 7 ids, see below). Each one now fires `ANIM.ASM`'s real `ATTACK_ON`/`ATTACK_ON_Z`/`ATTACK_OFF` (`wm_arcade_ani_attack_on(_z/_off)`, real and ctest-verified since fix38) at the exact frame hand-traced from its own `HRTSEQ2.ASM` source -- not guessed from the flattened `wm_visual_sequence` frame data, which (like every `wlanim.py --slice` extraction) linearly concatenates a source routine's branchy paths regardless of which one a real hit/block/miss actually takes. This sets a real `attack_mode`/`attack_xoff`/.../`WM_MODE_CHECKHIT` on the actor. 5 of the 6 attacks also carry a real, instant `ANI_SETFACING` right at their own start (`HRTSEQ2.ASM`, before any `WL` frame) -- `wm_bret_backend_change_anim` now translates it too, gated on the animation actually (re)starting so it fires once per selection like the source, not continuously; `hrt_4_kick_anim` is confirmed (by reading its own header) to be the one real exception with no `ANI_SETFACING` at all. Wiring this also turned up a small separate gap: `hrt_4_super_kick_anim` (`HRTSEQ2.ASM:1334-1335`) is a literal `SUBR` alias of `hrt_2_super_kick_anim`, not distinct artwork, so `WM_BRET_ANIM_SUPER_KICK4` now maps to the same real data and hand-traced attack window `SUPER_KICK2` already had, instead of staying unmapped.
- **Five more of Bret's real strikes are wired end to end, and the attack-window tracing is no longer by hand.** `tools/wlattack.py` reports, for each inline `ANIM.ASM` command in a routine, the 0-based index of the `WL` frame it immediately precedes -- reusing `tools/wlanim.py`'s own routine-scan and stop rules by importing it, so the two always agree on what "frame N" means. It reproduces all six previously hand-traced windows exactly (index and operands), which is what makes it trustworthy for animations nobody has traced yet. Using it, `WM_BRET_ANIM_BUTT2/BUTT4` (the close-range headbutt `do_punch` falls back to inside `near(50,45)`), `KNEE2/KNEE4` (the close-range knee `do_kick` falls back to), and `UPPERCUT4` (the crouching uppercut `do_super_punch` selects on a down input) now resolve to their real extracted `HRTSEQ2.ASM` frame data, carry their real `ANI_ATTACK_ON` windows (`AMODE_HDBUTT,19,75,35,24` at frame 5; `AMODE_KNEE,11,44,51,49` at frame 4; `AMODE_UPRCUT,-6,22,64,100` at frame 5), and get the real `ANI_SETMODE,MODE_UNINT|MODE_NOAUTOFLIP` + `ANI_SETFACING` header treatment the six already-wired attacks had. `src/generated/bret_frame_geometry.c` grew from 187 to 215 real frame geometries to match, so these five also produce a real per-frame `hurt_box` and can be confined and hit like the rest. Wiring them also exposed a genuine modelling error in `test_bret_backend_charge_face_rake_fires_on_release`: it held PUNCH for 100 ticks without ever advancing the animation, so the headbutt that press really selects stayed mid-swing forever. It only passed before because `BUTT2/4` resolved to nothing and therefore never set `MODE_UNINT`; the test now ticks the backend like the live match loop does, and `wm_arcade_bret_release_charge_face_rake`'s real `MODE_UNINT` precondition is exercised instead of bypassed.
- **Bret's stomp and ground punch, and attack windows that fire more than once.** `wm_bret_attack_window_t` used to hold exactly one `ANI_ATTACK_ON` per animation id, which is all eleven previously-wired attacks happen to have. `hrt_2/4_stomp_anim` genuinely fire two pulses each (an `AMODE_HITCHECK` probe, then the `AMODE_STOMP2` hit) and `hrt_2/4_ground_punch_anim` three (a probe, then two separate `AMODE_LBOWDROP2` elbow drops), each a distinct attack box with a real `ANI_ATTACK_OFF` between them. The table is now keyed on (id, frame) instead of id alone -- one row per real pulse -- so the whole `ON`/`OFF`/`ON` shape the source writes out is reproduced instead of silently dropping every pulse after the first. With that, `WM_BRET_ANIM_STOMP2/STOMP4` (what `do_kick` selects on a grounded opponent inside `near(160,140)`) and `GROUND_PUNCH2/GROUND_PUNCH4` (what `do_punch` selects on the same test) resolve to real frame data and real attack boxes; `src/generated/bret_frame_geometry.c` grew 215 -> 247 real frame geometries to match. These four are also the only wired attacks whose own `ANI_SETMODE` header adds `MODE_OVERLAP` (real, and genuinely read by `wm_arcade_combat.c`'s wrestler-overlap test), and the two stomps alone lead with an explicit `ANI_SETPLYRMODE,MODE_NORMAL` -- both now translated, and neither of them applied to the attacks that don't carry them. Reading every wired attack's header through `tools/wlattack.py` at once also showed all of them lead with an `ANI_ZEROVELS` before frame 0 that this port had never fired, so that is now wired uniformly for all of them rather than only for the new ones. `scripts/regenerate_source_data.sh` was brought back in sync at the same time: it had drifted to six sequences while `src/generated/bret_attacks.c` carried eleven and `bret_defense.c` wasn't regenerated by it at all, so the generated files could no longer be reproduced from the script that claims to produce them; re-running the updated script now reproduces `bret_defense.c` byte-identical and `bret_attacks.c` purely additively.
- **The tool now decides which animations can honestly be wired, and five more are.** Picking candidates by eye turned out to be unreliable: four animations that looked like obvious plain strikes (`BUTTS2/4`, `HAIR_PICKUP2/4`, `SHOOTER2/4`, `RAISE_ARM2/4`) are, on reading their real source, nothing of the kind -- `hrt_2/4_butts_anim` is a button-mash **repeat loop** that fires its attack once per iteration and ends by turning into the uppercut (`ANI_CHANGEANIM`); `hrt_2_hair_pickup_anim` and `hrt_2_shooter_anim` have no `ANI_END` at all and **fall through** into their own 4-facing twin; `hrt_2_raise_arm_anim` `ANI_GOTO`s into the middle of `hrt_4_raise_arm_anim`; and the 4-facing hair pickup and shooter are full puppet/grapple routines (`LEAPATOPP`, `ANI_ATTACHZ`, `ANI_SETOPPMODE`, `ANI_SUPERSLAVE2` against a puppet table). A flat `wlanim.py --slice` of any of those is not a truncation of one real playthrough, it is a frame list no playthrough ever plays. So `tools/wlattack.py --audit` now answers that question directly, sorting each routine's control flow into **blocking** (backward loop, `ANI_CHANGEANIM`, fall-through, a jump out of the routine, `ANI_SUPERSLAVE` rows whose frames `wlanim.py` cannot even parse), **unported** (`LEAPATOPP`, `ANI_ADD_MOVE`, `ANI_ATTACH` -- the frame list is fine, the gameplay command is not translated) and **tolerated** (forward skips and hit/miss forks, which is exactly what every already-wired attack has). Run against the 15 attacks already shipped, it clears all 15 -- that check is now a test, so the audit cannot quietly start calling shipped work broken. Run against everything else Bret's dispatcher can select, it named six honest candidates, of which five are now wired: `PUSH4` (the shove `mode_block` uses to break a blocker off), `JUMP_KICK4`, `KNEE_FALL4`, `KICK_TB` and `HEAD_HELD_STAND3`. `JUMP_KICK4` in particular had been living on a documented one-tick `MODE_UNINT` stopgap because it had no frame data to time a real one from; it now gets properly-timed protection like every other wired attack, and that stopgap list is one entry shorter. Wiring `KICK_TB` also needed mid-animation `ANI_SETPLYRMODE` (`MODE_INAIR2` for the leap, `MODE_NORMAL` on landing), so that is now a real (id, frame) table rather than the stomp-only special case batch 2 left behind -- which is also what lets `HEAD_HELD_STAND3` genuinely release `mode_headhold`, the entire point of that animation. Geometry grew 247 -> 264 real frames.
- **A pre-existing N64 link break, found by the same sync pass.** `src/generated/bret_defense.c` was added to the CMake host build in batch 1 but never to the N64 `Makefile`, so `wm_bret_block4_anim` had been an undefined symbol in the ROM build since then. Both it and the new `bret_grapple.c` are in the N64 source list now.
- **A real sourcing-parity defect, found by going through the remaining ids in order.** `HRTSEQ2.ASM` contains *two* different super-punch routines: `hrt_4_super_punch_anim` (:223), which `BRET.ASM:213 #scrt_cut` selects for the supercut secret move, and `hrt_2/4_super_punch2_anim` (:618/:677), which `#spunch_slap`'s own `FACE24 hrt,super_punch2_anim` selects -- and `FACE24` (`MACROS.H:51`) expands to exactly the `_2_`/`_4_` pair on the `MOVE_UP` facing bit, which is what `do_super_punch` reaches in ordinary play. An earlier cycle merged the two on the belief they named the same routine, deleted `WM_BRET_ANIM_SUPER_PUNCH4`, and asserted `SUPER_PUNCH2_2` permanently unmappable because "no `hrt_2_super_punch_anim` exists" -- true of that spelling, but the actual `hrt_2_super_punch2_anim` was there all along. They are different animations with different attack boxes (`AMODE_UPRCUT,-6,40,64,90` at frame 5 versus `AMODE_URN,19,75,35,24` at frame 3), so every ordinary super punch had been firing the supercut's box. Separated again: `SUPER_PUNCH4` is restored and holds `hrt_4_super_punch_anim` for the supercut, and the `SUPER_PUNCH2_*` pair now resolves to its own real extracted `super_punch2` data and window.
- **A dangling `if` in the attract state machine.** `app.c`'s `AMODE_LOOPS < 2` music guard (`ATTRACT.ASM:669 TURN_SOUNDS_OFF_IF_NEED`) had no body of its own and captured the following `break`, so the DCS command was sent unconditionally and, from the third attract loop onward, `WM_ATTRACT_DCS_LOGO` fell straight through into `WM_ATTRACT_SHOW_SPORTS_LOGO`'s entry body and ran it while the call was still `DCS_LOGO`. The source's gate suppresses *sound*; it never skips or re-enters a call. GCC had been flagging this as `-Wimplicit-fallthrough`; the warning is gone and the regression test was confirmed to fail against the original code, not just pass against the fix.
- **Routine chaining: the extractor now follows animations that don't end where their text ends.** A `SUBR` body carrying no `ANI_END`/`ANI_REPEAT` does not stop where the source text stops -- execution runs straight on into the words that follow, which is either the next `SUBR` (`hrt_2_hair_pickup_anim` into `hrt_4_hair_pickup_anim`) or the label of the body's own trailing unconditional `ANI_GOTO` (`hrt_2_raise_arm_anim`'s `ANI_GOTO,#cont`, landing inside `hrt_4_raise_arm_anim`). `tools/wlanim.py` now follows both, and `tools/wlattack.py` shares the same walk order so the audit judges -- and the reported frame indices refer to -- exactly the stream that gets extracted. A routine is only as sliceable as everything it chains through, so blockers propagate across the chain. All 21 previously-shipped sequences come out byte-identical. Two latent extractor bugs surfaced doing this and are fixed: a local label sharing a line with its frame (`#cont<TAB>WL 5,H4SL4C+FR1`) had that frame silently dropped, and chain targets were resolved from the top of the file even though local labels like `#cont`/`#hit`/`#missed` are reused across dozens of routines -- which resolved `hrt_2_raise_arm_anim`'s `#cont` to an unrelated earlier routine and produced frames from the wrong animation entirely. Neither affected any shipped extraction (checked), but both would have on the very first chained one.
- **Two more animations wired, and they are ones that could not have been before.** `KNEE_TO_HEAD4` (what `mode_headheld`'s punch/kick/punchkick branches select) and `FAKE_HOLD3` (what the head-hold monitor selects when the last headhold was under 120 ticks ago) both end in an `ANI_GOTO` into a shared tail. Under their own labels alone they extract as 1 and 3 frames; chained, they are 8 and 6 -- and `KNEE_TO_HEAD4`'s real `ANI_ATTACK_ON,AMODE_KNEE,11,44,51,49` sits at frame 2, past the end of the fragment, so that window simply could not have existed before. `FAKE_HOLD3` is off the one-tick `MODE_UNINT` stopgap list too, leaving 7 ids on it.
- **`ANI_SET_RPTCOUNT` loops are real now, not flattened.** `ANIM.ASM`'s `RPT_COUNT` mechanism (`_ani_set_rptcount:3530`, `_ani_dec_rptcount:3552`, `_ani_if_rptcount:3257`) makes a span of an animation play several times before the stream continues past it. `wm_visual_sequence` carries that span as `loop_first`/`loop_last`/`loop_count` and the runtime honours it, so an `ANI_ATTACK_ON` **inside** the span genuinely re-fires once per pass -- which is what the source does, its attack sitting inside the loop body. Unrolling into the flat frame list was the tempting shortcut and would have been wrong: it bakes one fixed length into data whose real length isn't always fixed. `tools/wlanim.py` refuses, loudly, the three shapes it cannot represent rather than inventing a number -- a **negative** `ANI_SET_RPTCOUNT` means `RNDRNG0(-n)`, a count drawn at runtime (`hrt_4_raise_arm_anim`'s own `-4`); a count of `1000` is an until-something-stops-it loop, not a fixed-length animation; and an `ANI_IF_RPTCOUNT` that branches *forward* (`hrt_uppercuts_to_head_anim`) is a first pass plus a separate repeated block sharing one counter, which a single span cannot describe. Three ids are wired as a result: `PIN2`, `PIN4` (35 and 33 frames, ~1300 ticks each, no attack window) and `KNEES_TO_HEAD`, whose first `ANI_ATTACK_ON,AMODE_HEADKNEES,4,34,70,54` is inside its loop and its second, `4,54,70,34`, after it -- so it lands four attack windows per playthrough from two table rows. Geometry grew 267 -> 287 real frames.
- **`ANI_CHANGEANIM` is a terminator, and reading it as one unlocked eight animations at once.** `ANIM.ASM:1301 _ani_changeanim` overwrites `OANIPC` **and** `OANIBASE` with the target animation and never returns -- so the routine genuinely ends there and the target begins. The source says so itself: the `.word ANI_END` following an `ANI_CHANGEANIM` is commented out in 16 places across `HRTSEQ2`-`4`. Treating it as an ordinary mid-stream command made these routines read far longer and far messier than they are -- `hrt_fall_back_anim` came out as 55 frames with four transitions when it is 12 frames with one, and `hrt_flying_kick_anim` as 38 rather than 9 -- and that inflated reading was what made the whole group look like it needed conditional-path evaluation it does not. With the extractor and the audit both stopping there (and the frame indices `tools/wlattack.py` reports stopping there too, which they briefly did not), eight ids are wired: `BUTTS2`/`BUTTS4` (whose window sits inside an `ANI_SET_RPTCOUNT,3` span, so one table row lands three headbutts), `FLYING_KICK`, `TBUKL_LEAP`, `RUNNING_GROUND_PUNCH`, `COMBO_PUNCH` and `COMBO_KICK` (three pulses each) and `FALL_BACK`. The per-animation header-mode-bits table generalised at the same time, so `MODE_NOCOLLIS`, `MODE_NOCONFINE` and `MODE_NOGRAVITY` are now honoured where the real headers carry them, not just `MODE_OVERLAP`. Geometry grew 287 -> 320 real frames.
- **The `ANI_CHANGEANIM` hand-off, and a correction to how it was detected.** An animation that ends by *becoming* another now genuinely does: the target starts through the ordinary `change_anim` path, so it gets its own header commands, attack windows and mode bits rather than inheriting the previous animation's. `TBUKL_LEAP` chains twice for real -- leap, hit the ground face down, get up -- and `FALL_BACK` (what the death path already selects) now runs on into `FACEUP_GETUP` instead of freezing on its last frame. Four ids were added purely as transition targets (`FACEDOWN_GETUP`, `FACEUP_GETUP`, `FACEUP_GETUP2_4`, `HITONGROUND_FACEDOWN`); none is selected by any dispatcher branch, because nothing *chooses* a getup -- it is what the fall before it turns into. Geometry grew 320 -> 337 real frames. This also **corrected the previous cycle**: treating every `ANI_CHANGEANIM` as a terminator was too broad. It only replaces the terminator when nothing after it ends the routine any other way -- the shape the source writes with `.word ANI_END` commented out below it. `hrt_2_butts_anim` reaches its transition when its repeat loop runs out but still has a real `ANI_END` on the button-mash `#ex` path, and `hrt_facedown_getup_anim`'s sits inside an `ANI_IFNOTSTATUS` free-toss branch with the ordinary ending below it. Both had been truncated at a transition they do not unconditionally take -- `BUTTS2`/`BUTTS4` shipped one frame short as a result, now fixed -- and only genuinely unconditional transitions are taken.
- **The ROM build was broken, and now there is a test that says so.** The N64 target is built with libdragon, which is not present in every checkout, so nothing in CI ever compiled it -- and its source list in the `Makefile` had drifted from `CMakeLists.txt`. Six symbols' worth: `wm_arcade_confine.c`, `wm_arcade_drone_data.c`, `wm_arcade_joystat.c`, `wm_arcade_mode_dead.c` and `wrestler_backend.c` were all missing, on top of the `bret_defense.c` omission found earlier. The ROM could not have linked. A full ROM does need libdragon, but catching this class of drift does not: `tools/n64_link_check.py` compiles the ROM's *own* C source list for mips64 with an ordinary cross-compiler and does a relocatable link, then reports any symbol the list fails to define along with the file that defines it. All 94 present core files compile clean for the real target word size and endianness under `-Wall -Wextra` with zero warnings, and the link is clean. It runs as the `ctest` target `wm_n64_link` and skips itself when no cross-compiler is installed. Verified to fail, naming the right files, when a source is removed again. This does not mean the ROM *runs* -- only that it no longer fails to link, and that list regressions are now caught by `ctest` rather than by nobody.
- **Wired attacks actually move now, and the motion data is generated rather than typed.** Every attack in this port played its real frames and set its real attack box while standing perfectly still, because `ANIM.ASM`'s inline motion commands were never translated. `tools/wlcommands.py` now emits them per animation -- `ANI_OFFSET`, `ANI_SET_XVEL`/`YVEL`/`ZVEL`, `ANI_ZEROVELS`, `ANI_ZERO_XZVELS`, `ANI_MIN_YVEL`, `ANI_FRICTION` -- each with the 0-based index of the frame it precedes, and `src/core/anim_frame_commands.c` applies them with the real semantics (x negated when the facing bit is clear, `MIN_YVEL` never lowering, `ANI_OFFSET` an instant nudge that also flips with facing). 126 commands across 36 animations. Rows are keyed on the animation's own **source label**, not a port-side enum id, so the same generated table serves any wrestler whose sequences get extracted -- there is nothing Bret-specific in it. - **Gravity, and the ground under it.** Until now every velocity this port wrote went nowhere. The reaction code has always set real launch velocities straight out of the source — `victim->y_vel = FX16(6)` for a body slam, `attacker->y_vel = FX16(4)` for a leap — and the animation VM has always run `ANI_SET_YVEL`/`ANI_ZEROVELS`. **Nothing added a velocity to a position.** What stood in for it was `wm_integrate_position`, a placeholder moving X and Z, documented in its own header as *"NOT a source routine"*. - **`ANI_WAITHITGND` is the payoff: 767 uses, the single most common untranslated opcode in the machine.** It is not an instant command — it holds the frame that is showing and re-tests every tick until the wrestler is on the ground, then plays `SMALL_BOUNCE` and runs on. That is how every knockdown, slam and throw waits for its landing. One rule in it is load-bearing: while `MODE_KEEPATTACHED` holds a live grapple and the victim is not `MODE_GHOST`, it is the **victim** hitting the ground that ends the wait — a slam ends when the man being slammed lands, not when the slammer does. With it, `hrt_kick_TB_anim` is a real turnbuckle leap: he rises from the mat to a peak 52 units up, holds the airborne kick frame for the whole descent, and lands 30 ticks later — and *that* is when its `ANI_SETPLYRMODE,MODE_NORMAL` fires, which is what the test beside it had always claimed ("once he lands") and never actually exercised. `ANI_BOUNCE` (`:950`), `ANI_WAITHITOPP` (`:2300`) and `ANI_SETLONG` (`:3913`) landed with it — **1,220 more command occurrences emitted, 82.6% → 87.5% of every `ANI_*` across the eight playable wrestlers.**
- Three findings worth keeping. `ANI_WAITHITOPP` is not a command with operands at all — the source's own note is *"just like an ordinary WL ticks,frame type command except that the ANICNT is zeroed if we hit the opponent"* — so one source line is a mode set plus an ordinary frame, and landing cuts the hold short through `wrestler_veladd`'s own `#set_yvel`. `ANI_SETLONG` names a raw process field, and across the whole roster it names exactly two (`OBJ_GRAVITY` 115 uses, `DEBRIS_X` 148); a third would be a silent write to whatever sits at that offset, so anything else refuses. And **gravity is per-animation**: every `change_anim` resets `OBJ_GRAVITY` to `GAME.EQU`'s `GRAVITY`, which is what lets `hrt_flyout_anim` give itself a heavier fall (`0E000h`) for the drop out of the ring and put the default back afterwards — without that reset one heavy fall would leave the wrestler heavy for the rest of the match.
- One coupling had to be fixed to make any of it observable: the flat `wm_visual` track beside each program used to run on its own clock, and it could never keep up once a program could wait — a fall parks the program on one frame for as long as it takes to land, and the flat list has no such command in it, so the two drifted apart by the length of every fall. The flat track now steps when the **program** steps, one frame for one frame. Matching on the frame *name* was tried first and is wrong: `hrt_2_punch_anim` shows `H2PL3B01` twice in a row and `H2PL3B02` twice in a row, so a name search finds the frame the track is already on and never leaves it.

- **A knocked-down wrestler can now get up, and the whole loop is real.** `ANI_WAITROLL` (`ANIM.ASM:2990`, 171 uses) is the other half of the ground system: it parks the animation, forces `MODE_ONGROUND` *"just to be safe"*, waits out `IMMOBILIZE_TIME` and `GETUP_TIME`, and then calls `WRESTLE2.ASM:1290 do_roll` — and it is do_roll answering **"did not roll"** that lets the animation move on. Letting go of the stick is what gets him up. `hrt_tossed_anim` runs end to end now: thrown and launched, `ANI_WAITHITGND` for the landing, `ANI_GETUP,STAY_TIME`'s 270 ticks on the mat, the roll, then `ANI_CHANGEANIM,hrt_faceup_getup_anim`.
- **`do_roll` and its eight per-wrestler tables** (`tools/wlroll.py` → `src/generated/roll_frames.c`). Each is a speed, a Z velocity and an inverse multiplier followed by a frame list, and `do_roll` runs an 8-bit `ROLL_POS` through the multiplier to pick the frame. The lists are **not** in ascending order — Bret's runs `FR1`, then `FR13` down to `FR2`, because that is the direction his artwork rolls — and holding up rather than down negates both the advance and the Z velocity, so the frames run the other way too. `Z_BOUND` stops him once he is within 6 of it. One detail preserved rather than tidied: the multipliers are written as expressions like `10000h*12/255` and the assembler's divide **truncates**, so Bret's comes out 3084, the largest index 255 can reach is 11, and his thirteenth frame is unreachable in the shipped game.
- **The getup meter** (`WRESTLE.ASM:2538`), which is what makes any of that playable: `GETUP_TIME` counts down one a tick, and **any button or stick press — or its release edge — takes three more off**. That is the mash-to-get-up mechanic; the source's own comment is *"As long as getup_time has a value, he is stuck."* Reaching zero clears `PLYR_DIZZY` and `STARS_FLAG`. With it, a 270-tick stay-down becomes ~69 ticks of mashing. `ANI_GETUP` (`:52`) is what sets it, and it refuses while `PLYR_DIZZY` is set. This also closes a loop `wm_arcade_lifebar.h` had flagged: `adjust_health`'s `#will_die` path defers a death by setting `i_will_die` instead of killing outright, and the header noted it *"needs an eventual consumer this port doesn't have"* — `ANI_WAITROLL` is that consumer, and it calls `clear_lifebar` when the debt comes due.
- `ANI_ROT` (`:4441`) came with it — *"just sit and do nothing"*, the source's own comment: it holds the current frame and never advances, which is how `xxx_dead_anim` keeps a dead wrestler down. It is a **terminator for span purposes** even though it is not an `ANI_END`, which is what lets `xxx_dead_anim` be emitted at all (it is four commands and a rot, with no frames). It had to be, because `ANI_WAITROLL` hands off to it. **519 programs, 88.3% of every `ANI_*` across the eight playable wrestlers.**
- **A defect shipped in the gravity commit, found and fixed here.** `wlprogram`'s `MOTION_OPS` — the set deciding which ops get their operands written into the generated C — was a **hand-kept list**, so an op added to the command table but not to that set fell through to the no-operand default and had its operands silently emitted as zero. `ANI_BOUNCE`'s upward kick became 0 and `ANI_GETUP`'s stay time became 0. Neither test caught it: the bounce test checked the extractor's tuple rather than the emitted C, and the fall test passed on the *first* launch, which comes from a different opcode. The set is **derived from the command table** now, and a test checks both the derivation and the two real values in the generated file.

- **The combo meter, and a damage rule that was correct and unreachable.** Two counters, easy to confuse: `COMBO_COUNT` is per wrestler, bumped by `ANI_INC_COMBO` (183 uses), and it is what `adjust_health` reads — a hit landed while it is non-zero does **fixed** damage of `-max(10-COMBO_COUNT, 4)` instead of the normal scaled amount. `wm_arcade_lifebar.h` had said so in its own notes: *"nothing yet increments combo_count anywhere."* `PLT_COMBO_SIZE` is per player, grown by `ANI_ADD_MOVE` (273) through `LIFEBAR.ASM:750 ADD_TO_COMBO_COUNT`, and it is the meter **bar**, tripping a super flash at 16. `ANI_CLEAR_COMBO` (208) is **both ends** of a combo depending on whether the count was already set: starting one gives the victim an 80-tick immobilize the source labels *"Time opponent has to execute combo breaker"*; ending one holds his getup meter off for ten seconds. `hrt_combo_punch_anim` now runs a real six-hit combo end to end.
- One quirk recorded rather than tidied: `ADD_TO_COMBO_COUNT`'s own comment is *"Adds first value each time! [why?]"* — and the reason is that its "already added once" branch only skips re-setting `a3` from `a5`, which `movk 1,a5` has just made 1 as well. The bar grows by exactly 1 every call whether or not the move was already counted, and the `COMBO_START` bookkeeping affects nothing but `COMBO_START`.
- **A prerequisite that was a live defect of its own.** `WRESTLE.ASM:2503`'s five per-wrestler countdown timers — `DELAY_BUTNS`, `SAFE_TIME`, `DELAY_METER`, `IMMOBILIZE_TIME`, `WALK_FAST` — were being **set** all over this port (React1-5, the special moves, the attach opcodes) and counted down by **nothing**. - **The `ANI_CODE` tail, and the file-scoping trap all the way through it.** Sixteen more routines take the bridge from **1,251 to 1,339 call sites (54% → 58%)** and from 40 to 56 of the 141 distinct routines — all the self-contained actor-arithmetic class, no subsystem behind any of them. - **A defect in the first tail batch, and the guard for it.** All thirteen rows shipped unreachable: a `#`-prefixed label is file-scoped, the emitter carries the `#` into the generated op, and the lookup is a plain `strcmp` — so a row spelled `set_zvel2` never matches a call site spelling it `#set_zvel2`. Their unit tests passed because they called `wm_anim_code_run` with the un-prefixed name **directly**, testing the row rather than the wiring. The reported "58%" was wrong for the same reason: the measurement stripped the `#` from uses and matched a `#`-less registry pattern, which over-counted globals *and* hid `#make_black`'s eight rows. There is now a source-tool test that every registry row matches a real call site, spelled exactly, and that a file-scoped row is called from the file it names.
- **Second tail batch: `ANI_CODE` at 1,413 of 2,303 (61.4%), 63 of 145 names.** `#set_opp_xflip`, `fix_bnc_flip`, `#ckongrnd`, `#inc_loop`, `#zero_butn`, `set_position`. - **The announcer's voice queue exists now.** Every routine in the announcer speech group ends the same way — `CREATE` a process, `SLEEP`, then `ADD_IF_SILENT`: *"say this, but only if the announcer has nothing else to say."* Without the queue that arbitration has nowhere to happen, which is why the whole group (`CALL_MISSES` alone is 177 call sites) was stated as a gap rather than translated. `wm/arcade/wm_arcade_announcer.h` translates `DCSSOUND.ASM`'s side of it: `RESET_VOICE_QUEUE`, `ADD_VOICE` with its real `OUT_OF_RANGE_SOUND` refusal, `IF_SILENT_ADD_VOICE`'s `CMP A1,A2 / JRNE NO_ADD` gate, and `ANNOUNCE_VOICE` draining one line per tick through the same `triple_sound` seam as every other sound, reporting which side of `:2880`'s `0E0h` split each line fell on. There is **no sound-completion signal** in this port, so `ANNOUNCE_VOICE`'s play-and-`PRCSLP`-until-done becomes a caller-set `busy_ticks` hold, `0` meaning back-to-back. And the ring **loses a full lap** rather than growing — two bare cursors with no count read a wrapped-onto-itself write cursor as empty, which is exactly what the source does, since it has no overflow check either. - **And the announcer actually says things now: `ANI_CODE` 1,413 → 1,730 of 2,303 (61.4% → 75.1%), 63 → 70 names.** `CALL_MISSES` is the single biggest `ANI_CODE` routine in the game at 197 call sites, and it has no body: like its eleven siblings it is three lines — `CREATE` a `SOUND_PID` process, `SLEEP`, `ADD_IF_SILENT` with a table address and a percentage. So the routine *is* data, and `tools/wlvoice.py` reads all of it out of `DCSSOUND.ASM`: the twelve callers with their real sleeps and percentages (`MISSES` 350‰ after 5 ticks, `SPECIAL_MOVE` 550‰ after 10, `DROP_KICK` 400‰ after 15…), the thirteen line tables they draw from, `SET_UP_PERSONAL_CALL`'s five per-wrestler tables, and `ASCENDING_TABLE`. - **`ADD_TO_QUEUE` itself is translated**, in the source's own order: the `.WORD -1` at `-050H` clearing `REPEAT_STATE`; the `RNDPER` gate; `RNDRNG0` over the row count at `-020H`; the six negative sentinels that mean "this row is a *personal* line" resolved from the attacking wrestler's number; `ARE_WE_REPEATING`'s four-line memory, and the forward walk it does when the row it drew was said too recently; then `ADD_VOICE` or `IF_SILENT_ADD_VOICE`, and the extra words of a two-line row until a zero. `REPEAT_MODE` works as written too — one row of it starts a counter that climbs `ASCENDING_TABLE` and, while it lives, *takes over* every announce call regardless of table or percentage, until `REPEAT_DUMMY`'s 80 ticks run out.

- **Every wrestler grunts in his own voice now: `ANI_CODE` 1,923 → 1,983 of 2,303 (83.5% → 86.1%).** `impact_sound` (38 uses) and `DO_GRUNT` (22) are two lines of assembly each — all the behaviour is in `DCSSOUND.ASM`'s tables, and there are three layers of them. `MASTER_SOUND_TABLE` is a 9×59 word grid indexed `[WRESTLERNUM][move]`, with the source's own note on the layout: *"the first two are the noises a wrestler makes when he throws the move, and the second two are the noises he makes when he's hit with it."* A negative entry means `DEFLT` (`8000h`) — read `DEFAULT_SOUND_TABLE` instead. And what comes out does **not** go straight to `triple_sound`: `table_sound` (`DCSSOUND.ASM:1330`) tests `btst 12,a0`, and an index with bit 12 set names one of **67 random sub-tables** that `RNDRNG0` then draws from — which is why a wrestler's grunt is redrawn on every hit rather than fixed. `tools/wlwrsnd.py` extracts all of it.
- **The file-scoping trap again, and this time it decides which body 38 call sites get.** `MACROS.H:246` — `SUBR` emits a `.def` and is global; `SUBRP` does not and is file-local. `impact_sound` is `SUBR` in `YOKSEQ3.ASM` and `SUBRP` in `HRTSEQ4.ASM` and `RZRSEQ3.ASM`, and the bodies **differ**: the global one plays an extra `WRSNDX HDBUTT_L1,HDBUTT_L2` on the wrestler himself before the rug slam, the local ones only do the slam. So eleven of Bret's own animations call the Undertaker-file version *with* the headbutt sounds, and one calls Bret's own *without*. `DO_GRUNT` is the same shape: `SUBR` in `SHNSEQ2.ASM`, and a bare label in `LEXSEQ3.ASM` — also file-local — which uses `WRSND` with a **fixed** `W_LUGER` instead of reading `WRESTLERNUM`. Resolving either by bare name gets one of the two wrong for everybody.
- Three things the data itself says. **Four wrestlers reuse another's row verbatim** — the Undertaker, Shawn and Luger are byte-identical to Bret, and Adam Bomb to Yokozuna — which matters because a drifted 59-word split would look exactly like that, so the extractor counts each commented block independently and requires both readings to agree. **Nothing in the shipped grid is a zero**, so `WRSNDX`'s `jrz DONE?` on a wrestler's own entry is unreachable as written; the thirteen zeros are all in the default table, where they do mean silence — and `GRABFLING_T1`, the first of `DO_GRUNT`'s two sounds, is one of them, so the grunt is a single sound for every wrestler who defers there. And the random sub-tables **alias**: `#doink_kick_a`, `#doink_knee_a` and `#doink_slam_a` are three labels stacked on one `.word` line, so Doink's kick, knee and slam draw from the same three sounds.

- **Measuring what's left, and finding two defects by doing it.** The emitter silently skips any `ANI_*` it does not model — that is deliberate, and unlike the flat extractor it cannot corrupt frame order — but it meant the only answer to *"how much of the animation VM is missing"* was a hand-kept one, which is exactly how the `MOTION_OPS` defect shipped. `wlprogram.py --census` now counts them: **51,168 ops emitted, 2,102 skipped — 96.1%** across 1,524 programs, and it names the call sites. The remainder is overwhelmingly renderer (`ANI_SHAKER` 451, `ANI_SHAKEALL` 389, `ANI_DEBRIS` 197, `ANI_ATTCHIMAGE` 194). But the census also listed ops the emitter *claims* to handle — `ANI_GOTO` 7, `ANI_IFSTATUS` 4 — and a silently dropped branch is not a gap, it is a wrong animation.
- **A local label may begin with a digit.** Five do — `HRTSEQ4.ASM`'s `#4block` and `SHNSEQ3.ASM`'s `#4`, `#2`, `#4xc`, `#2xc`, named after the 2-count and 4-count pin they lead to — and the label pattern required a letter after the `#`. They were invisible on **both** sides: their definitions were not seen as labels, and the six branches to them were dropped. `SHNSEQ3`'s gsuplex animations are where that showed: `choose_2or4` sets `MODE_STATUS` to pick whether Shawn's victim lands face-up (a 2-count) or face-down (a 4-count), `ANI_IFSTATUS,#4` takes the face-down arm and `ANI_GOTO,#2` skips it — with both dropped, the animation ran through **both arms**, playing the face-up frame *and* the face-down frame and doing `ANI_FACEUP` then `ANI_FACEDOWN`. The `#4 WL 1,S4ST4C+FR1` line lost its frame outright too, because the label-strip that handles a label sharing a line with its frame failed the same way.
- **And an animation does not always start at op 0.** Fixing the labels surfaced the second one. A routine can branch *back* into shared code earlier in the file — every wrestler's `*_4_hitblock_anim` jumps into his `*_4_block_anim`'s hold at `#4block`, which is how getting hit while blocking returns you to blocking — and the emitter already grew the body backwards so the branch had a target. What it never recorded is that the routine's **own** first command is then some ops in. **42 of the 1,524 programs are like that**, and every one had been starting by playing code it merely jumps into: `hrt_4_hitblock_anim` opened on the block-hold frame instead of its own, and `bam_combo_pogo_anim`'s body starts **256 ops** into its stream. `wm_anim_program` carries an `entry` now and `wm_anim_exec_start` begins there. Both defects have regression tests that were confirmed to fail against the old code, not just pass against the new.

- **The end of a match is announced now.** `CALL_MATCH_OVER` (`DCSSOUND.ASM:3793`) is the one caller in the announcer family that is a *decision tree* rather than a table and a percentage, so its constants are read out of the source individually rather than guessed: the process's `SLEEPK 5`; a 20% `RNDPER` that hands the line to the **wrestler** instead of the announcer, out of his own `*_FINISHES` table; the winner's `p1winstreak` against `CMPI 4`, and another 20% for one of two over-four-wins lines chosen by a further `RNDPER 500`; and otherwise `ADD_TO_QUEUE` at **1000 per mille** — not `ADD_IF_SILENT`, so the end of a match always says something, over whatever the announcer was already saying. `xor a8,a9` picks the table: `MATCH_OVER` when a *player* lost (the source's own comment, *"Lawlor cheers/Vince gripes"*) and `MATCH_OVER_DL` when a drone did. That makes ten more of the extracted tables live, including all seven `*_FINISHES`.
- Three things this family does differently, all now recorded rather than smoothed. It has **no reset-repeat word of its own**: these tables were written with just a `.LONG crowd` and a `.WORD count,stride`, so the word `ADD_TO_QUEUE` reads at `-050H` is whatever happens to sit there — the last data word of the table before it, or, for `HART_FINISHES`, the low half of a `.LONG` in the `WHICH_WRESTLER_TALKS` pointer list above it. Accidental, but real, and it decides whether the call clears `REPEAT_STATE`. It also has **no walk-forward rows**: every row is drawable and nothing follows, so a wrestler with a single line who just said it fails `ARE_WE_REPEATING` and the original walks straight off the end into whatever the assembler put next — this port stops and says nothing. And **the Undertaker and Yokozuna win in silence**: their tables hold a single `0`, which is "no line", not line zero.
- `MATCH_OVER_DL`'s first row is `GIVE_CREDIT`, so what the announcer actually says there is the **loser's** personal line resolved through `SET_UP_PERSONAL_CALL` — the machinery that landed with the queue, doing real work now.

- **Five more self-contained routines: `ANI_CODE` 1,983 → 2,021 of 2,303 (86.1% → 87.8%), 78 of 145 names.** `set_xdrift` (14 uses), `set_buckoff_vels` (7), `skick_delay` (6), `tgt_ground` (6), `tgt_tbukl` (5) — each reads and writes only the actor it is given, plus ring geometry. `set_xdrift` is the source's own *"Leap at the center of ring!"*: in the ring, and only outside a `60h` deadband, a flat 3.0 of X velocity toward the middle. `set_buckoff_vels` is being thrown off the turnbuckle — pushed toward the middle in X and Z, popped 5.0 upward. `skick_delay` is a two-second lockout between super kicks, reported through `MODE_STATUS`, with the source's own comment on the refusal: *"This blocked fling attempt is too close (in terms of time) to most recent grab."*
- Four details worth keeping. `set_xdrift` measures from **`RING_X_MID` (1024), not `RING_X_CENTER` (1074)** — the two are 50 apart and it is easy to reach for the wrong one. `tgt_tbukl` aims at **`RING.ASM`'s** `vln_*_rope`, whose right-hand X is five units from `WRESTLE.ASM`'s `vln_*_rope_r` that the port already had, so both are kept as separate constants rather than folded together. `skick_delay` writes its `LAST_SKICK` stamp **before** the comparison, so a refused attempt still restarts the window. And its royal-rumble early-out skips the check entirely in a mode this port has no equivalent of — the flag is 0, so the check always applies, which is the shipped behaviour of every match this port can actually run.
- `TGT_XOFF`/`TGT_YOFF`/`TGT_ZOFF` are on the actor now. `ANIM.ASM:1428` is explicit that filling them is the caller's job — *"NB - user must set TGT_XOFF,YOFF & ZOFF <-- these are the actual target"* — so the routines that set them are translated ahead of `ANI_LEAPATPOS`, which reads them and is not.

- **An `ANI_CODE` routine can move the program counter, and now one does: `ANI_CODE` 2,021 → 2,037 of 2,303 (87.8% → 88.4%).** `HRTSEQ3.ASM:2896 #rope_check` (16 uses) is the roll-uppercut hitting the ropes, and it does something no other translated routine does: `movi #stand,a14 / move a14,*a13(ANIPC),L`. **`ANIPC` is a field on the wrestler, not state inside the interpreter** — so a routine sets it and the VM applies it the moment the routine returns, which is exactly how it is modelled here. Resolving a label at runtime needs the labels, so the emitter now exports them: every program carries its own `#name -> op index` table (4,571 labels across 1,524 programs, ~73 KB), and `wm_anim_program_label` looks one up. The rest of the routine is real too — `CAN_MOVE_DIR` masked with `MOVE_LEFT|MOVE_RIGHT` to ask "am I against a rope", the matching bank wobbled through the rope seam, and the `03Ch` thump.
- **And where it jumps is a bug in the original, kept as written.** `#rope_check` is a single `SUBRP` shared by `hrt_roll_uppercut_anim` *and* `hrt_combo_roll_uppercut_anim`. It always writes `#stand` — which is a label inside the **plain** animation. The combo one has its own tail, `#standc`, and that is the one that does `DO_COMBO_MESS` and `ANI_CLEAR_COMBO`. So a **combo** roll-uppercut that ends against the ropes runs the plain animation's ending: no combo message, no cleared count. `#standc` is defined once and branched to from nowhere — dead code in the shipped ROM, which the test asserts directly (`#stand` is not in the combo program at all, so the jump has to leave it). This port hands it over as a `become` of `hrt_roll_uppercut_anim` entered at `#stand`, with `ANIPC` surviving the hand-off, because that is what a flat address does on the real machine.

- **Three more, and Doink is different again: `ANI_CODE` 2,037 → 2,058 of 2,303 (88.4% → 89.4%), 82 of 145 names.** `MAYBE_BOUNCE_ROPE` (8 uses) is *"into the ropes!"*, but only sometimes — `MOVK 10,A0 / RNDRNG0 / MOVE A0,A0 / JRNZ` speaks only on a draw of exactly zero, and `RNDRNG0`'s maximum is **inclusive**, so that is one time in eleven rather than one in ten. It needed the announcer queue, which is why it waited. `#clrcnt` (5) is one clear, with the source's own note on the odd choice of field: *"We are re-using BUT_COUNT in the player process."*
- `#set_trgt` (8) is where to land when climbing out onto the apron, and it is **the file-scoping trap once more**: seven of the eight copies put it at `RING_X_CENTER ± (0f8h+60)`, and **Doink's is `0f8h+50`** — ten units further in. Resolving by bare name would put him on everyone else's apron. It is only translatable now because `TGT_XOFF`/`YOFF`/`ZOFF` landed with the last batch.
- One thing worth knowing about the RNG, found by writing the test for that one-in-eleven gate. `RAND` stirs from **`HCOUNT` and the stack pointer** — real entropy on the hardware, and *none at all* in a bare test: with no readers wired it settles on a single value and returns it forever. The app feeds it tick-derived versions of both, so the live game is fine, but a test that builds its own `WmRng` and expects variety gets a constant. The tests here drive it through the documented latched-input path instead, in the same shape the app uses.

- **The self-contained tail, cleared: `ANI_CODE` 2,058 → 2,095 of 2,303 (89.4% → 91.0%), 92 of 145 names.** Ten more routines, none of them needing a system behind it. `check_xvel` (8 uses, a global seven other files call) stops a toss that would carry the victim out over the ropes — heading further out, he is reversed to 1.5 inward and it reports through `MODE_STATUS`, with the source's own note on why: *"Will land on ropes"*. `inc_loop` (8) is the Undertaker's chokehold counter. `#reduce_dmg` (4) is `MACROS.H:714`'s `SPCDMG` — stamp `SPECIAL_DAMAGE_TIME` and arm `NEXT_DAMAGE`. Plus `#reattach`, `SET_OPP_GRAV_NORM`/`_LOW`, `target_whoihit`, `#set_opp_facing`, `#blocked_vels`.
- **Three of the ten differ per file, and the differences are all constants** — so they are the registry's `param` rather than three bodies. `#reduce_dmg` is `RD_PILEDRIVER` (22) over 80 ticks for Razor, `D_STOMP2` (6) and `D_PUNCH` (8) over 40 for Shawn and the Undertaker. `#go_high` — *"Go higher for last hit!"* — pops the opponent 5.0 for Doink and Bret and only 4.0 for Razor, and all three decline to lift Yokozuna at all, with a two-word explanation: *"Yoko too fat"*. Doink's copy also keeps a commented-out earlier version that read `ATTACH_PROC`, with the note *"Got rid of this because attach_proc is a zero after a hit"* — which is why all three read the closest wrestler instead.
- Left out of this batch on purpose: `#pause_opp` needs the opponent's `OANICNT`, the animation tick counter, which lives in his interpreter rather than on the wrestler — half of it (the `MODE_UNINT`) would be worse than none. `#flsh_wht` is `flash_white`, palette rendering.

- **Seven more singles: `ANI_CODE` 2,095 → 2,102 of 2,303 (91.0% → 91.3%), 99 of 145 names.** `#zero_x_4` (*"Don't float if dropping straight down"*), `#delay_whoihit`, `#ck_flip`, `#ck_dead_opp`, `#set_wrestler_xflip`, `#stop_dmg`, and `#no_bk_xvel` — which is **the file-scoping trap one last time**: the global `no_bk_xvel` kills only `OBJ_XVEL`, and `SHNSEQ3.ASM`'s local copy kills `OBJ_ZVEL` as well. Both are now registered, and a test asserts the difference directly. `#ck_flip` is worth a note too: its two halves test the sprite's flip bit with **opposite senses** (`jrz` on the left, `jrnz` on the right), which is exactly what makes each side end up facing into the ring.

- **The self-contained tail is finished: `ANI_CODE` 2,109 of 2,303 (91.6%), 104 of 145 names.** Five last routines — `#check_xvel` (a *different* routine from the global `check_xvel`: push him 2.0 the way he is facing, and kill the Z drift with it), `#grunt` (`WRSND W_SHAWN,...`, naming the wrestler outright like `LEXSEQ3`'s `DO_GRUNT`), `#hit_ground`, `#set`, and `#choose_2or4`. Two nice endings: `#set` turned out to be `#delay_whoihit`'s body with a different window (eight seconds against 55 ticks), so both share it with the window as data; and `YOKSEQ4`'s local `#choose_2or4` is **byte-identical** to `SHNSEQ4`'s global one, so for once a file-scoped copy shares the body rather than needing its own — with a test that asserts the two agree, in case that ever stops being true.
- **What was left at that point was 194 uses in 41 names, and every one of them blocked on a system rather than on reading more assembly.** Measured: 80 uses want the renderer (`create_impact*`, `start_smoke`, the salt and debris routines, palette flashes), 39 want round-end and pins (`win_announce`, `grnd_hit`), 24 want a crowd (`DO_CROWD_CHEER`), 21 want the roster sweep and `calc_line_x` (`set_tbukl_confine`, `hit_nearest`), 14 want tournament state (`spunch_delay`), and 7 want process creation. Two of those six are done below; `tools/ani_code_census.py` is the number, so it is reproducible rather than quoted.

- **An independent reading of the animation streams, and what it does and does not settle.** Everything in `tools/` shares `wlanim.py` — its lexer, its label patterns, its routine spans — so a mistake in that layer is invisible to every generator built on it, and the flat-extractor cross-check only ever had partial independence. `tools/wlverify.py` shares **nothing**: its own comment stripping, its own routine spans, its own label scoping, its own branch resolution, its own read of `WRESTLE.CMD`. And it **runs** the animation rather than re-extracting it, so what comes out is the frame sequence actually played — which checks the emitter and the interpreter's tick model together, end to end.
- **294 animations, all identical — frames and tick counts, zero divergences.** Both checks are confirmed to fail against a deliberately perturbed frame duration, and against one in an animation only the independent reader covers, so neither is passing by construction. It also caught 24 animations it could play that were never emitted; all 24 turned out to be **Adam Bomb**, the cut wrestler, in files `WRESTLE.CMD` never links — so the verifier now reads the linker's own object list, and a genuine missing program would fail the test.
- **The limit is the point, and it is a real one.** `wlverify.py` can only play bodies made of frames, `ANI_GOTO`, `ANI_REPEAT`, the repeat counter and `ANI_PAUSE`. Every conditional branch and every wait — `ANI_IFSTATUS`, `ANI_WAITHITGND`, `ANI_CHANGEANIM` and the rest — makes a body unverifiable, so **the interesting half of the VM is exactly what is excluded**: 192 of 1,524 programs, and by construction the simplest ones. This raises confidence in the frame and tick backbone. It says nothing about the branching semantics, and nothing at all about the arcade — there is still no reference to compare against. One caveat recorded in the tool: `ANI_SETSPEED` is treated as stream-neutral because this port's interpreter never reads it for tick counts, which means this check *cannot* tell whether the original scaled frame durations by it.

- **The `ANI_SETSPEED` question, settled — and it was a real hole.** The independent verifier had to treat `ANI_SETSPEED` as stream-neutral because this port's interpreter never read it, and I flagged that as unresolved rather than assume it. It is resolved now, from the source: `ANIM.ASM:151` genuinely **does** scale a frame's duration by it — `move *a13(ANI_SPEED),a1 / mpyu a0,a1 / srl 8,a1` — and then shifts the result again by `hyper_speed_on`, `AWARD.ASM`'s double-speed powerup. So `100h` is identity, and the port was silently dropping the whole mechanism.
- **Why nothing broke: every one of the 1,220 `ANI_SETSPEED` commands in the entire source drop is `100h`**, and `hyper_speed_on` is a powerup toggle that is 0 in normal play. The port was right by a fact about the *data*, not by construction — the exact shape of defect that has bitten repeatedly here. The scaling is implemented now, so it is right by construction instead, and the port gets the hyper-speed powerup for free. Only a **frame's** count scales: `ANI_PAUSE` (`:1252`) and `ANI_HMBWAIT` write `OANICNT` directly, and the tests assert that asymmetry rather than assuming it.

- **Widening the independent check, and a negative result worth keeping.** Extending `wlverify.py` to model conditional branches looked like the obvious next move; measuring first showed it would add **ten** animations (192 → 202), because the real blockers are the *waits* and `ANI_CHANGEANIM` (`ANI_WAITHITGND` alone blocks 537 bodies), not conditionals. So that plan was dropped before it was built.
- What did pay off was fixing two gaps in the **reader itself**, both found by comparing its frame lists against the emitter's across the whole roster: `SUBR` labels **alias** (`bam_stand2_anim` is immediately followed by `bam_stand8_anim` with one body under both, so the first was getting an empty body), and a frame's tick count is sometimes a small **expression** (`WL 2+1,B2WL1A+FR4`). Strict independent coverage went **192 → 294 animations**, still all agreeing exactly.
- **The check that was not shipped, and why.** A whole-roster frame-subsequence comparison reaches 92% agreement (1,339 of 1,455), and the residual 116 are not divergences: they are the two documented emitter behaviours — bodies grown across routine boundaries, and cross-routine branches like `bam_run2_anim`, whose entire body is `ANI_GOTO,#run2` into *another routine*. Making that check green would mean replicating the emitter's span logic inside the thing meant to check it independently. It is left as a measurement rather than a test, because a check that has to copy its subject is not a check.

- **The sprite bundler was NOT generalised, and the measurement is why.** Pointing it at the whole roster was the plan; costing it first killed it. Bret's bundle is 303 frames for **1.8 MB of payload** (5.8 KB a frame, 11.2 MB of generated C). The roster names **4,861** frames — about **29 MB uncompressed**, on top of an `anim_programs.c.o` that is already 2.46 MiB of cartridge (that figure was 3.5 MB here until the ROM was actually measured -- see the cartridge budget below; the argument does not change). `tools/wimpimg.py` says why in its own header: the WIMP containers are the **artist format, before the arcade's own LOAD2/DMA2 packing**, so this is the unpacked floor and the real arcade ROM stored it packed. And an N64 has **4 MB of RDRAM** (8 with the Expansion Pak) — 29 MB cannot be resident under any packaging. Expanding every frame into a linked C array is the wrong shape; the art has to stay packed on cart and be DMA'd per frame, which is what the original did. That is a design decision, not a refactor, so it is written down rather than half-built.
- **A regression I introduced, found by the invariant sweep.** `xxx_dead_anim` is not part of the roster sweep — `scripts/regenerate_source_data.sh` adds it with an explicit `--animation WRESTLE2.ASM xxx_dead_anim`. Regenerating the file by hand with just `--roster --slave-targets`, which I had been doing, **silently dropped it**, and `anim_program.c`'s death path sets `exec->become = "xxx_dead_anim"` — which then resolved to nothing and ended the animation quietly. There is a test now that every hard-coded `become` target in the C resolves to a real program, confirmed to fail against exactly that mis-regeneration. `ANI_ROT` also joined the terminator set: it parks forever rather than ending, which is how `xxx_dead_anim` finishes.

- **Tournament state and the crowd, both real: `ANI_CODE` 2,109 -> 2,147 of 2,303 (91.6% -> 93.2%), 104 -> 106 names.** Two of the six systems the previous entry called blockers turned out to be answerable from the source rather than from a subsystem this port lacks.
- **`spunch_delay` (14 uses) needed a gate, not a tournament.** `DNKSEQ3.ASM:2256` is `skick_delay`'s twin — the same two-second super-punch lockout reported through `MODE_STATUS` — behind three lines of match configuration: `move @royal_rumble,a0 / jrnz #ok`, then `@PSTATUS` against 3 (two humans), then `@NUM_OPPS` against 1. The interesting part is that `skick_delay` has this same gate *commented out* in the source, so the two were written together and one had it disabled. `wm_anim_env` now carries `royal_rumble`, `pstatus` and `num_opps` and the routine **evaluates** them; this port only ever starts the `PSTATUS==0` attract match or the single-human `#1plyr` one and only ever creates one opponent, so the gate resolves to "check" today — but it resolves by reading the values, so a match type added later gets the source's own behaviour instead of an assumption baked into a comment.
- **`DO_CROWD_CHEER` (24 uses) is two instructions, and the crowd tables are data.** `CROWD.ASM:1119` is `MOVK C_OVERIDE|C_LONG,A3 / CLR A4` falling straight into `crowd_cheer` — so the routine *is* its arguments, and `crowd_cheer` itself walks `NUMCROWD` members of `CROWDDATA` swapping each one's `SCPTR` for its `CHEER1`/`CHEER2` script. That is a sprite subsystem this port has not got, so it is reached through `wm_anim_env` exactly like `triple_sound` and the rope commands, with `GAME.EQU:299-306`'s real flag bits.
- **Which also closed a hole I had written down and left open.** `ADD_TO_QUEUE`'s `MOVE *A2(-040H),A3,L / JRZ NO_CROWD / CALLA DO_CROWD_ANYWAY` had been translated as a comment saying the port has no crowd. It has one now: `tools/wlvoice.py` extracts the **eight** crowd tables at `DCSSOUND.ASM:4443` (a one-word header and four words a row — sound, duration, flags, `RNDPER` value — which is why `DO_CROWD_ANYWAY` picks a row with `SLL 6,A0`), and `wm_announce_table` carries the `.LONG` that names one. So the announcer's own reactions genuinely fire: `MISSES` -> `CROWD_FAIL`, `SETUP_MOVE` -> `SETUP_TABLE`, `CLIMB_ROPES` -> `CRESCENDO_TABLE`, and the **crowd runs before the line's percentage gate**, so a refused announcer line still cheers. `CROWD_DUMMY`'s own `crowd_dummy_exists` flag — the reason a row carries a duration at all — is modelled as the match's countdown, so a second draw inside one sound's life cheers without re-triggering the sound.

- **A pin now ends the round: `ANI_CODE` 2,147 -> 2,186 of 2,303 (93.2% -> 94.9%), 106 -> 109 names.** The third of the six blockers. Until now a round could only end by knockout — `wm_arcade_round.h`'s `get_live_bits` plus the 5-second pin-idiot-check countdown — and a wrestler who actually got pinned just lay there while that clock ran.
- **`win_announce` (39 uses) is three instructions and one process.** `DNKSEQ2.ASM:5202` CREATEs an `ANNC_PID` running `LIFEBAR.ASM:2642 announce_rnd_winner` and calls `KILL_PIN_HIM`. The process is where a round ends, and `wm/arcade/wm_arcade_round_announce.h` translates it down to the round award and the end-of-match announcement, with the two buckoff helpers it leans on (`anyone_bucking`, `set_all_buckoffs`) and `set_winner`'s own KO-branch winner search — "the first live wrestler, preferring one whose `DID_PIN` is set", plus the `#bogus` fallback the source's own comment calls *"really bad and should never happen"*, which is translated because a pin genuinely can leave the pinned man's whole side dead. The buckoff branch is the interesting half: if anyone is trying to buck off, the process sleeps 90 ticks at `arw_bwait`, wakes, clears everyone's `NEW_BUCKOFF`, and **only then** asks `get_live_bits` whether both teams are somehow still alive — the straight-through pin path has no such check, which is exactly why a pin ends a round outright.
- **`grnd_hit` (28 uses), "FOR USE ONLY IN PINS!"** — and the source argues with itself in the margin about whose pointer to use, one comment saying use `CLOSEST` because you do not attack during a pin and the next overruling it: *"Un! DO use WHOIHIT, as this is set in all the pin_anims before this function is called."* It puts the victim into **his own** `hitonground` animation (indexed by the victim's number, through the same `change_anim1a` seam `ANI_SLAVEANIM` already uses) and aligns the two in Z, pinner one unit in front — unless the pinner is the Undertaker, who is left where he is. Its `#hit_t` is a per-wrestler table no opcode names, so `wlpuppet.py` gained a fourth kind keyed by the routine that reads it: the *site* is named by hand, the nine rows are still read out of `DNKSEQ2.ASM`, and a test checks each one is a program this port can actually play.
- **`#setopp_deadanim`** sets `M_DEAD_ANIM` — PLYR.EQU's *"If killed, don't change anim"* — on whoever this wrestler is attached to, so a victim who dies mid-move finishes the move instead of being yanked into his death animation.

What was missing was the flow: init and load at power-on (`TABLE_CMOS_CHECK` builds the factory tables when there is no save, which is what a fresh machine does), an offer when a credit ends, the input, the commit, the write back out. The offer is the **win-streak** table, taken before the streak is cleared, because game over in this port means the player lost and `WINSTREAK_TAB` records the run that just ended. Whether a row qualifies is not this port's decision: `wm_hs_begin_*` runs the source's own `FIND_LOW_TABLE_LEVEL` and refuses, the same way `SELECT.ASM:211` calls `DO_BEATEN_GAME` unconditionally and lets the table logic say no. The source's `auto_init` cache is kept, so a player who typed his initials once this credit does not type them again.
- **The persistence decision, made once and written down: a 16 kbit cartridge EEPROM.** `wm/arcade/wmania_hiscore_persist.h` deliberately does not choose -- it takes two callbacks and says the port supplies them -- so the host build keeps the encoded bytes in RAM and `src/platform/n64/hiscore_eeprom.c` points the same two at libdragon's `eepromfs`. The tables encode to **1,130 bytes**: a 4 kbit EEPROM is 512 and cannot hold them, a 16 kbit one is 2,048 and can. Controller Pak would also fit but is removable and shared with other games, and these tables are the machine's rather than the player's -- an EEPROM soldered to the cartridge is the closer analogue of the CMOS the source checks with `TABLE_CMOS_CHECK`, down to failing over to the factory tables when the checksum does not hold. A cartridge with no EEPROM, or one too small, is refused rather than half-written, and the game then runs on factory tables exactly as a new machine does. The file cross-compiles clean for mips64 against the real libdragon headers.

- **A blunt measurement rule was erasing a finished routine, and the fix is one word wider than the rule.** `shake_all_ropes` read as `cited` — *named only in prose* — although a real translation of it sits in `anim_code.c`. The cause is the callback-seam carve-out: `code_ids -= seam_ids` drops a seam name from the identifier pool **outright**, wired or not. That is the right rule (a NULL-checked call keeps a name alive exactly as a declaration does, so "declared but never used" catches almost nothing), but it cannot tell *seam only* from *seam **and** a real function of the same name*. It now has one exception: a seam name survives when the port also **defines a function** of that name. A definition is safe where a declaration and a call are not — none of the twelve routines the carve-out was written for had one; being seams and nothing else was the whole of what was wrong with them. Measured against the tree as it stood, the exception changes **exactly one** routine's status and no others.

- The rest of `confine_wrestler` beyond the in-ring branch: `ATTACH_PROC` paired-actor movement and rope-wobble bounce velocity/sound on first contact, `ck_climb_out_top/bot/side` (already translated as pure logic in `wm/arcade/wmania_ring_climb.h` via an earlier fix38 chunk, but triggering a climb is a presentation concern this port doesn't wire to any animation system yet), the `#outring` branch's remaining geometry (`ARENA_TOP/BOT`, the fence lines, and the mat2-edge climb-in overlap check). **The reason once given for leaving it -- "genuinely unreached since `in_ring` never leaves `1`/true, no ring-out/knockback system clears it" -- is no longer true, and is corrected rather than quietly dropped:** `anim_code.c:2979` clears it, and it was *measured* clearing on the live loop while the victory pose was being wired -- a dead opponent's own death animation rolls him out, `in_ring` 1 -> 0, within two ticks. The branch itself is translated; what is left is the fence geometry, not the reachability, and the `PLYRMODE==RUNNING` gate-crash tail (needs `FACETBL`/`FACE24TBL` animation-table dispatch this port hasn't translated).
- `wm_arcade_calc_closest`'s own scope: it only computes real deltas/distance against the one fixed `smart_target` opponent this port ever has. `calc_closest`'s multi-candidate ranking loop (`biased_range`, `ONGROUND`/`WHOIHIT`/`INRING`/previous-closest/combo/Z-distance biasing, the running-behind-us skip rule, and `CLOSEST_NUM` selection itself) is not translated -- moot until a real ladder/teammate system exists to choose among more than one opponent -- and `calc_closest2`'s every-4th-tick recompute throttle (a pure CPU-cost optimization) isn't either, since recomputing one distance every tick is trivial.
- What death doesn't do yet. Death sound (`triple_sound 034h`) is still not wired, but the reason once given for that no longer holds and is corrected here: it said `wm_arcade_bret_callbacks_t.sound` "is never wired anywhere", so a bridge for one call would be inconsistent. **That seam is wired now**, along with Razor's and the six shared dispatchers' `sound_label`, through `wm/wrestler_sound_labels.h` and the existing `WRSNDX` tables. The death call is a plain `triple_sound` from the reaction path rather than a dispatcher `WRSND`, so it wants that path's own pass. The `#grnd` convulse_t/hitonground dispatch and the `#will_die` `HEADHELD` death-deferral are both real but permanently unreachable, since this port's Bret dispatcher never sets `WM_PMODE_ONGROUND`, `WM_PMODE_DEAD`-at-time-of-a-second-death, or `WM_PMODE_HEADHELD`. `flash_red` is pure lifebar-rendering feedback with no rendering system here.
- **What `match_winner` does now, and what it still doesn't.** This bullet used to say the score was real but nothing reacted to it -- *"the match doesn't end, restart into round 2, or present a winner … no announcer … no `DO_ROUNDS` round-2 reset"*. **All of that has since landed, and the bullet was simply stale.** `announce_rnd_winner` runs end to end, including the `SLEEPK 20` tail and the `WRESTLERS_RESET` that starts the next round; `DO_WAIT` ends the match and sets `match_over`; the round is awarded either by the announcer or by this port's KO-countdown stand-in; `increment_wincount` and the award tally run on the real path. What is genuinely still absent is **presentation**: no on-screen round clock, no win-count text or winner token drawn, no crowd rendering -- the decisions exist and nothing paints them. The `PINHIM_ANIM_PID` pin-attempt window is still absent too, so `set_winner`'s `DID_PIN`-priority search stays moot for a fixed pair.
- Full credit/buy-in/start/select orchestration: the selection mechanics/data core is translated, but original credit processes, text, mug objects and final screen rendering still need their shared backends.
- The complete 131-command animation interpreter, branch/pointer relocation, all wrestler visual banks and wrestler-specific process logic.
- Full background header/palette object construction, fonts/text, fades and remaining frontend routines.
- Collision/ropes/turnbuckles, grapples, damage/pins/finishers, original CPU behavior and DCS audio backend.

Anything still missing stays absent or is reported in the generated frontiers. Harness code does not substitute for the game.

## N64 controls

The N64 layer maps controller state into portable arcade actions. Current bring-up mapping is:

| N64 | Portable action |
|---|---|
| Analog stick / D-pad | movement / frontend direction |
| A | run |
| C-Left | light punch |
| C-Up | power punch |
| C-Right | light kick |
| C-Down | power kick |
| R | block |
| Start | arcade attract/start input path |
| Z | N64-only debug HUD |

The final frontend/gameplay input behavior follows source routines as they are translated; the harness mapping is not treated as authoritative arcade behavior.

## Cartridge budget

```sh
python3 tools/n64_rom_budget.py
```

**44.58 MiB of a 78 MB cartridge, 59.9% used.** 8.92 MiB of code and
generated tables plus a 35.66 MiB DragonFS payload; `.bss` is 0.67
MiB, which is the tighter number, being RAM on a 4 MiB machine. The
tool compiles the ROM's own source list for mips64 and sums the
sections that occupy cartridge space, so the figure is checked on
every `ctest` run (`wm_n64_budget`, failing past 85%) rather than
estimated once. It classifies by ELF flags, not section names --
`anim_programs.c`'s 2.4 MiB of pointer tables land in
`.data.rel.ro.local`, which a name list missed. `docs/N64_FIRST.md`
has the breakdown and the caveats.
