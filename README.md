# WWF WrestleMania Arcade -> N64 source port (r9 source-engine pass)

**Primary target:** Nintendo 64 / libdragon.  
**Porting rule:** when the arcade source implements it, translate that implementation and use its original data/assets. Do not replace it with invented N64 behavior.

r9 is the first broad **shared-engine** pass. It is not a claim that the complete arcade game is already playable. The point of this revision is to replace one-off bring-up code with reusable source-driven systems that whole parts of the original program can execute on.

## What r9 actually translates

- **53 Hz arcade source clock.** `DISPLAY.EQU`'s source tick rate runs independently of 60 Hz N64 presentation, so translated sleeps, timers, processes and animation cadence are no longer accelerated to 60 Hz.
- **Cooperative source-process scheduler.** Shared CREATE/sleep/kill-by-PID behavior is used by translated frontend processes instead of hand-coded screen timers.
- **Packed BMOD records.** The original 64-bit background block records are decoded generically; CI extracts `NTITLESCBMOD` and `SPORTBKBMOD` directly from `BGNDTBL.ASM`.
- **Original BLIMP title artwork.** `BIGWWF.BDB`/`BIGWWF.BDD` are decoded into their 40 CI8 blocks and six RGB555 palettes, cross-validated against `NTITLESCBMOD`, and rendered from the original packed block records rather than a flattened WIMP crop.
- **Original title sparkle artwork/process lifetime.** All 69 WIMP frames named by `MISC.LOD` from `SPARKLE.IMG` are generated as source sprites. `show_title` creates/kills the source `FLASH_PID` and `ATTRACT_ANIMPID` processes alongside `cycle_lava`. The shared `SPRINKLE_GLINTS`/`RANDOM_SPARKLE` helper bodies and `WHERE_WRESTLMANIA_SPARKLES` table are absent from the checked-in WWF tree, so placement/random cadence is clearly marked provisional rather than source-exact.
- **Typed animation stream.** Mixed WORD/LONG operands are preserved. Implemented commands execute source operand widths and direction rules; unknown commands fail closed instead of being guessed.
- **Whole-source dependency IR.** CI scans every `SUBR`/`SUBRP`, static call/process edge and unresolved dynamic edge, with frontiers rooted at `attract_mode` and `start_match`.
- **Whole-source animation IR.** CI mechanically preserves typed WORD/LONG animation data and W/L packing macros across the historical ASM tree.
- **Source selection core from `SELECT.ASM`.** The 2x4 cursor grid, exact crouton coordinates, source BMOD placement, player start/mug/sound data, `scramble_table` roster mapping, attributes, legal four-way movement, START+UP random-selection gate, random wander/home rules, 15-second source selection timer and 30-tick final wait constants are translated in portable C.
- **Source-driven attract execution.** Initial 8-tick blank, active source routine order, DCS/Midway/title timing, Midway background movement, title lava scheduling, and the source title sparkle process lifetime remain source-driven.
- **Original artwork paths already proven on N64.** Midway Sports uses the original 17 WIMP pieces; title art is derived from original artist/BMOD data; Bret remains the first wrestler with the current visual backend.
- **`show_gameplay`'s attract-mode `start_match` creation path.** `ATTRACT.ASM::show_gameplay` is just `WRESTLE.ASM::start_match` run with `PSTATUS==0`; the `#0plyr` branch's `RNDRNG0(7)`-skip-7 wrestler draw, `LIFEBAR.ASM::init_life_data` (`LIFE_MAX`=163), and PLYRNUM/PSIDE wrestler-actor creation are translated (`wm/match.h`), on the real `SLEEP 3*60` + `wait_on_butn 10*TSEC` timing. See the boundary below for what this does not yet do.
- **Bret's live control layer and a real visual backend for it.** Whichever actor draws `WM_ROSTER_BRET` runs the actual `wm_arcade_move_bret` dispatcher every tick, not a harness. `wm/bret_backend.h` resolves `WM_BRET_ANIM_STAND2/4`/`TORSO2/4` and 7 of Bret's light/power punch/kick animation ids to their real `wm_visual_sequence` data and drives two `wm_visual_state` tracks (body + torso) from it -- the merge adapter `wm/arcade/wm_arcade_bret.h` itself calls for. Every other animation id, and every other wrestler, still resolves to nothing.
- **Real movement physics, and a real walk cycle to go with it.** `wm/movement.h` translates `WRESTLE.ASM::convert_facing` and `set_velocities` exactly (per-direction velocity table, `walk_fast`/opponent-ONGROUND-or-DEAD 1.5x boost, backward-facing 0.9x reduction) and wires `execute_walk`'s `MOVE_DIR`/`OBJ_CONTROL` (`M_FLIPH`) dispatch as Bret's real `execute_walk` callback. `wm/bret_backend.h` also now runs `change_walk_anim`'s leg-cycle half: all 12 `hrt_walkM_fF_anim` sequences `hrt_leg_anims_table` (`BRET.ASM:2897`) can select are extracted and wired, so a Bret actor with real input genuinely walks with the correct animation, not just a position change under a frozen sprite. `change_walk_anim`'s torso half (`hrt_torso_anims_table`, `BRET.ASM:2981`) is fully wired too, diagonal and all 12 off-diagonal turn-transition entries -- see the next bullet.
- **`FACING_DIR`/`NEW_FACING_DIR` are real state now, and turning genuinely animates.** `wm/arcade/wm_arcade_closest.h`'s `wm_arcade_update_newfacing` translates `WRESTLE.ASM:3018`'s `update_newfacing` (live `NEW_FACING_DIR` toward the opponent, every tick, for every actor -- wired into `wm_match_tick` unconditionally, exactly where `WRESTLE.ASM`'s own per-process main loop calls it), and `wm/movement.h`'s `wm_execute_walk` translates `set_rotate_anim`'s literal `FACING_DIR=NEW_FACING_DIR` catch-up for the `#zip`/stance case (`WRESTLE.ASM:5082-5083`). Just like the source, `FACING_DIR` stays frozen at its last idle value while actually walking -- `change_walk_anim`'s leg half never writes it -- so facing one way while walking another (e.g. after running past a repositioned opponent) is representable. Both actors also start the match with real position *and* facing from the same real `WRESTLE.ASM:2691-2755` `#set0` placement init (`wm/match.h`'s `place_wrestler`, `#teamX_starts` table: `RING_X_CENTER-85,1127+93,WM_MOVE_UP_RIGHT` for P1, `RING_X_CENTER+85,1103+93,WM_MOVE_DOWN_LEFT` for the opponent) instead of a zeroed default -- the two positions are chosen so each wrestler's real starting facing already points at the other's real starting position, so nothing spuriously turns on tick 1. `set_rotate_anim`'s own turn-animation *selection* for the `#zip`/idle-turn case is now wired too (`wm_bret_rotate_anim`, `hrt_rotate_anims_table`), and `change_walk_anim`'s torso half genuinely reaches and animates the off-diagonal (mid-turn) region of `hrt_torso_anims_table` while walking, using the real `hrt_N_to_M_turn2_anim` sequences -- each carrying one or two real `ANI_SETFACING` commands (`HRTSEQ1.ASM:460-524`) that `wm_bret_backend_tick` fires at their exact hand-traced frame, which is what actually promotes `FACING_DIR` while genuinely walking. `execute_walk`'s own INTURN freeze (`WRESTLE.ASM:5222-5252`) is wired too and load-bearing: without it the instant `FACING_DIR` catch-up would truncate every turn animation almost immediately. The leg turn anims' own `ANI_XFLIP` (4 of the 6 canonical bodies -- the two adjacent-quadrant ones never cross the sprite's own left/right mirror line) is wired too, toggling `OBJ_CONTROL`'s `M_FLIPH` at its real, hand-traced frame index, same mechanism as the torso's `ANI_SETFACING`. Diagonal entries still reduce to picking between `hrt_torso2_anim` and `hrt_torso4_anim` (`hrt_torso8_anim`/`hrt_torso6_anim` are literal `SUBR` aliases of those two in `HRTSEQ1.ASM`, not separate artwork, confirmed by extracting and diffing their frame data). Translating this also surfaced a real pre-existing gap: Bret's 6 attack animations lead with a real `MODE_UNINT` (`HRTSEQ2.ASM`) this port's simplified `change_anim` never propagated onto the actor, so an attack could get silently stomped by the new idle-turn reselection on the same tick -- `wm_bret_backend_change_anim`/`wm_bret_backend_tick` now set and clear it for real, matching the source.
- **A real, human-playable single-player match for Bret.** `WM_APP_MODE_MATCH_INIT` (after select/pregame) is no longer a dead end: `wm_match_start_selected` translates `start_match`'s PSTATUS!=0 `#1plyr` path using whatever the select screen actually chose, and `wm/human_input.h` maps real controller state onto the same `but_val_cur`/`stick_val_cur` fields `DRONE.ASM`'s commit path writes for CPU wrestlers, so a human playing Bret drives the real `wm_arcade_move_bret` dispatch, real movement and walk animation, and the real visual backend above with actual button/stick presses.
- **Real attack-box activation for Bret's 6 wired attacks** (now 7 ids, see below). Each one now fires `ANIM.ASM`'s real `ATTACK_ON`/`ATTACK_ON_Z`/`ATTACK_OFF` (`wm_arcade_ani_attack_on(_z/_off)`, real and ctest-verified since fix38) at the exact frame hand-traced from its own `HRTSEQ2.ASM` source -- not guessed from the flattened `wm_visual_sequence` frame data, which (like every `wlanim.py --slice` extraction) linearly concatenates a source routine's branchy paths regardless of which one a real hit/block/miss actually takes. This sets a real `attack_mode`/`attack_xoff`/.../`WM_MODE_CHECKHIT` on the actor. 5 of the 6 attacks also carry a real, instant `ANI_SETFACING` right at their own start (`HRTSEQ2.ASM`, before any `WL` frame) -- `wm_bret_backend_change_anim` now translates it too, gated on the animation actually (re)starting so it fires once per selection like the source, not continuously; `hrt_4_kick_anim` is confirmed (by reading its own header) to be the one real exception with no `ANI_SETFACING` at all. Wiring this also turned up a small separate gap: `hrt_4_super_kick_anim` (`HRTSEQ2.ASM:1334-1335`) is a literal `SUBR` alias of `hrt_2_super_kick_anim`, not distinct artwork, so `WM_BRET_ANIM_SUPER_KICK4` now maps to the same real data and hand-traced attack window `SUPER_KICK2` already had, instead of staying unmapped.
- **Hits actually connect.** The original `ANI3` hurt-box header (`SYS.EQU`'s `IANI3X`/`Y`/`Z`/`ID`) is confirmed unrecoverable from the checked-in tree: its `bretimg.tbl`/`bret.seq`/`imgtbl.glo` compile output is absent, and the WIMP `.IMG` directory format itself never carried it either (only `xani`/`yani`/`width`/`height`). `wm_bret_hurt_box_for_frame` (`wm/bret_backend.h`) substitutes each frame's own real WIMP image bounds instead -- real numbers, from a new geometry-only generated table (`tools/bret_geometry_bundle.py` -> `src/generated/bret_frame_geometry.c`) deliberately kept separate from `wm_bret_sprite_find`'s pixel/palette data, so hit-box math is engine logic that doesn't depend on which artwork happens to be linked in (host `ctest` included) and keeps working once stock art is replaced. `wm_bret_backend_tick` sets a real `hurt_box` from it every tick, and `wm_match_tick` now calls the real, ctest-verified-since-fix38 `wm_arcade_check_wrestler_collisions()`/`wm_arcade_wrestler_hit()` (`REACT1.ASM`) every tick via `wm_arcade_wrestler_hit_collision_callback`, with a real `adjust_health` translated from `LIFEBAR.ASM:1547-1670` (life clamped to `[0, LIFE_MAX]`, the 20+pt near-death "fudge", and "attract mode never dies"). A wired attack whose real attack box overlaps a real hurt box now genuinely reduces the victim's life.
- **A wrestler can actually die.** `wm/arcade/wm_arcade_lifebar.h`'s `wm_arcade_adjust_health` is the one real implementation of `LIFEBAR.ASM::adjust_health`'s damage-application tail, shared by both of its real callers: the `REACT1.ASM` hit path above, and `BRET.ASM mode_normal`'s own `I_WILL_DIE` self-death case (`wm_bret_backend_callbacks` now wires `adjust_health` for real instead of leaving it `NULL`, so that path no longer silently no-ops). Once life genuinely reaches 0 (not saved by the fudge or "attract mode never dies" rules), it sets a real `WM_PMODE_DEAD` and turns off further hit checks (`SETMODE DEAD` + `wres_collis_off`) -- or, when the attacker has an active combo, defers death by LIFEBAR's own 1-HP combo-revival rule (`I_WILL_DIE`, real but currently unreachable since nothing in this port sets `combo_count` yet).
- **Ordinary play actually throws a real punch.** `wm/arcade/wm_arcade_closest.h` translates `WRESTLE.ASM::calc_closest`'s per-opponent delta/distance computation (`closest_xdist`/`closest_ydist`/`closest_zdist`/`closest_dist` against `actor->smart_target`), and `wm_match_tick` now calls it every tick before `wm_arcade_move_bret`. `BRET.ASM`'s `do_punch` (`near(a,50,45)`) used to see a permanent `closest_xdist`/`closest_zdist` of 0 -- nothing computed them -- so every punch resolved to the unwired `WM_BRET_ANIM_BUTT2/4` headbutt regardless of range. With real distances, a human punching from realistic range now gets a real, wired punch animation and its real `ATTACK_ON` window through ordinary human-input play, not just direct backend calls.
- **A knockout is now genuinely detected.** `wm/arcade/wm_arcade_round.h` translates `WRESTLE2.ASM::match_timer`'s actual round-ending trigger on a KO -- not just its round clock running out: `get_live_bits()` (which `PLYR_SIDE`s still have a live wrestler) plus its real 5-second "pin idiot check" countdown once one side doesn't. `wm_match_tick` steps this every tick; once one side has been fully dead for 5 real seconds, `wm_match_state.round_state.decided`/`decided_winner_side` become real and correct (a simultaneous double-KO resolves as a draw rather than guessing at the unported PIN system's tie-break).
- **A round win is now genuinely scored, best-of-3 and all.** The instant `round_state.decided` flips, `wm_match_tick` awards it through `wm_arcade_match_score_award_round`, translating `LIFEBAR.ASM::set_winner`'s real KO branch: `wm_match_state.score` tracks real `p1rounds`/`p2rounds` and sets `match_winner` (1 or 2) the moment either side reaches `LIFEBAR.ASM`'s actual best-of-3 threshold of 2. The source's own `DID_PIN`-priority search among several survivors is moot here -- this port's fixed 1-on-1 match never has more than one wrestler per side to find. Nothing acts on `match_winner` yet -- see the boundary below.
- **Rapid hits actually deal less damage.** `wm_arcade_adjust_health` now stamps `victim->last_damage` with the real tick count on every call (`LIFEBAR.ASM:1593-1595`), unconditionally regardless of which of its own branches ran. `wm_arcade_wrestler_hit` (`REACT1.ASM`) already read `last_damage` for its rapid-hit reduced-damage window (a second hit within 50 ticks deals `WM_RD_*` instead of `WM_D_*`), but nothing had ever written it, so repeated attacks always dealt full damage regardless of timing -- a real gameplay difference, not just internal bookkeeping.
- **The first-hit and high-risk damage bonuses actually apply now.** `wm_arcade_adjust_health` also translates `LIFEBAR.ASM:1429-1466`'s own damage-shaping step: a nonzero `DAM_MULT` scales the incoming delta by `(1+DAM_MULT)/2` and is cleared, and an attacker with an active `COMBO_COUNT` replaces the delta entirely with `-max(10-COMBO_COUNT, 4)` (the second case is currently unreachable, same as the combo-revival case above -- nothing sets `combo_count` yet). `wm_arcade_wrestler_hit` was already real and ctest-verified since fix38 about *setting* `runtime->dam_mult` to 2 (first hit of the round) or 4 (a high-risk bonus hit), but nothing had ever consumed it, so those bonuses were computed and then silently discarded -- they now genuinely deal more damage.
- **Every hit is scaled the way a real 1-on-1 non-team match actually scales it.** `wm_arcade_adjust_health` now also applies `LIFEBAR.ASM:1471-1521`'s `damage_mod_table` lookup to any damage (never healing): the real table scales by active-drone-count and whether the target is a drone or a player, but `wm_match`'s `actors[]` is always the fixed pair `wm_match_start_attract`/`selected` create, so that count is always 0 -- and both of the table's 0-drones columns are the identical `_85PCT` (218/256) anyway, so no `PLYR_TYPE` branch was even needed.
- **`speed_adjustment` uses the arcade's real factory default, not a guess.** `LIFEBAR.ASM:1524-1528`'s further game-speed scaling reads an operator DIP-switch/menu setting (`ADJSPEED` via `GET_ADJ`) this port has no live settings subsystem for -- but rather than inventing a value, `WM_ARCADE_SPEED_ADJUSTMENT_16_16` uses the arcade's own factory-shipped default: `AUDIT.ASM`'s `FACTORY_TABLE` lists `ADJSPEED` (adjustment id 25) as `3`, exactly matching `LIFEBAR.ASM`'s own `BADCHK` fallback for an out-of-range read, and `LIFEBAR.ASM`'s `#timer_table` entry for that value is literally commented `"normal damage (default)"` -- i.e. the real factory default is precisely a 1.0x identity multiply. `wm_arcade_adjust_health` applies the real multiply-and-shift unconditionally (healing and damage alike); it's a no-op today, but wired for a live value the moment this port gets an operator-settings system.
- **Death doesn't just leave a wrestler as a statue anymore.** `wm/arcade/wm_arcade_mode_dead.h`'s `wm_arcade_mode_dead` translates `DOINK.ASM:2920`'s `mode_dead` -- the shared MODE_DEAD handler every wrestler's own `#mode_table[9]` points at, `BRET.ASM` included -- and `wm_bret_backend_callbacks` now wires it into `wm_arcade_move_bret`'s own `MODE_DEAD` dispatch instead of leaving it `NULL`. The real routine's job is deciding whether a freshly-dead wrestler gets a button-mashing "buckoff" comeback chance, gated on `@royal_rumble`, `is_8_on_1()`, and a combo-meter check (`CHECK_COMBO_GO`); all three are provably always false/zero in this port (no royal rumble mode, no 8-on-1 ladder battles -- both need the unported ladder/team system -- and no per-player combo-meter-fill tracking at all, since only life itself is real via `init_life_data`), so every branch collapses to the same real outcome: `WM_STATUS_NO_BUCKOFF` gets set once on a wrestler's first dead tick, and every tick after that is a genuine no-op through the source's own early-out checks. The buckoff/zombie-revival system those gates protect stays real (in the source) but unreachable here for the same reason.
- **The ring rope actually stops you now.** `wm/arcade/wm_arcade_confine.h`'s `wm_arcade_confine_wrestler` translates `WRESTLE.ASM:3074` `confine_wrestler`'s in-ring branch: `MODE_NOCONFINE`/`PLYRMODE==ATTACHED` early-out, Z bounds against `RING_TOP`/`RING_BOT`, and X bounds against the real left/right rope lines. The X check reuses fix38 Ring Chunk 1's already-translated boundary geometry (`wm/arcade/wmania_ring_geometry.h`) through a new `wm_ring_calc_line_x`, which computes `WRESTLE.ASM:5814` `calc_line_x`'s real per-Z interpolation directly (the closed form of the source's own precomputed-table setup routine, including its genuine one-step inset quirk) instead of caching a table this port has no boot phase for -- and reads `actor->hurt_box.x1/x2` exactly where the source reads `OBJ_COLLX1`/`OBJ_COLLX2`, since `wm_arcade_set_hurt_box` already computes byte-identical values (the same `set_collision_boxes` translation). Sets the real `WM_MOVE_*` bits in a new `actor->can_move_dir` field, which `wm_execute_walk` now reads for the real down-right/down-left redirect (`WRESTLE.ASM:5339-5384`) instead of always taking the un-redirected diagonal. Wired into `wm_match_tick` for the Bret actor only, right after its hurt_box is set fresh each tick. The source actually runs `confine_wrestler` twice per tick and ORs the results (`confine_wrestler_fix1`/`fix2`) -- that only converges because the collision box gets refreshed from the corrected position before the second call, and neither that second call site nor what refreshes the box is located in the checked-in source, so (confirmed by testing) a second pass reusing the same stale box diverges rather than converges; only the genuine single real pass is kept.

## What is deliberately *not* called a port yet

- The rest of `start_match`: `INIT_LADDER_TABLE`/`CURRENT_LADDER`/`NUM_OPPS` multi-drone team selection (both `#0plyr` and `#1plyr` fall back to one placeholder opponent), ring/rope/crowd/timer process creation, collision/pin/finisher lifecycle, and the `#2plyr` (two-human) path.
- The rest of the already-ported combat core's connection to a live match: `wm_arcade_move_ported_wrestler`'s generic 8-wrestler dispatch isn't used yet (only Bret is wired, directly); the other seven wrestlers have no visual backend, movement, or human control at all -- and their CPU opponent still runs the same idle-only drone described next. `DRONE.ASM`'s AI script/range data (`wnshort_t`/`wnmed_t`/`wnlong_t`, `blkbase_t`/`blkatk_t`/`sklhhdly_t`/`sklhrdly_t`) is emitted by a source macro (`SKLM`) that is not present in the checked-in tree, so it is not guessed -- a CPU-controlled wrestler (attract-mode or the human's opponent) never actually throws a button/stick input, so it never moves or attacks.
- The rest of `confine_wrestler` beyond the in-ring branch: `ATTACH_PROC` paired-actor movement and rope-wobble bounce velocity/sound on first contact, `ck_climb_out_top/bot/side` (already translated as pure logic in `wm/arcade/wmania_ring_climb.h` via an earlier fix38 chunk, but triggering a climb is a presentation concern this port doesn't wire to any animation system yet), the entire `#outring` branch (`ARENA_TOP/BOT`, the fence lines, and the mat2-edge climb-in overlap check -- genuinely unreached since `in_ring` never leaves `1`/true, no ring-out/knockback system clears it), and the `PLYRMODE==RUNNING` gate-crash tail (needs `FACETBL`/`FACE24TBL` animation-table dispatch this port hasn't translated).
- `wm_arcade_calc_closest`'s own scope: it only computes real deltas/distance against the one fixed `smart_target` opponent this port ever has. `calc_closest`'s multi-candidate ranking loop (`biased_range`, `ONGROUND`/`WHOIHIT`/`INRING`/previous-closest/combo/Z-distance biasing, the running-behind-us skip rule, and `CLOSEST_NUM` selection itself) is not translated -- moot until a real ladder/teammate system exists to choose among more than one opponent -- and `calc_closest2`'s every-4th-tick recompute throttle (a pure CPU-cost optimization) isn't either, since recomputing one distance every tick is trivial.
- What death doesn't do yet. `wm_arcade_adjust_health` flips `player_mode` to `WM_PMODE_DEAD`, and `mode_dead` (see above) sets a real status flag on the way to a permanently-unreachable buckoff system in this port -- neither one plays a death sound or dispatches the wrestler-specific death/ground animation (`WM_STATUS_DEAD_ANIM`, already set for real by `REACT1.ASM`'s hit-reaction path, is not yet consumed by anything).
- What `match_winner` doesn't do yet. `wm_match_state.score` is real, correctly-scored best-of-3 state, but nothing in `wm_match` reacts to it once it's set: `wm_match_tick` keeps stepping every actor exactly as before -- no `MODE_DEAD` wrestler resumes moving on its own (`wm_arcade_move_bret`'s `WM_PMODE_DEAD` case is a safe dead end), but the match doesn't end, restart into round 2, or present a winner either. There is still no `PINHIM_ANIM_PID` pin-attempt window (so `set_winner`'s `DID_PIN`-priority search, moot for this port's fixed pair, would matter the moment a real PIN system existed), no announcer, no crowd reaction, no on-screen round-clock display (`match_time`, `ADJSPEED`) or its own KO-independent `#tmout` award path, and no `DO_ROUNDS` round-2 reset (life/position/`round_state` all stay exactly as they were when round 1 ended) -- multiple rounds/a full match were never in scope here to begin with (see the ladder/team boundary above).
- Full credit/buy-in/start/select orchestration: the selection mechanics/data core is translated, but original credit processes, text, mug objects and final screen rendering still need their shared backends.
- The complete 131-command animation interpreter, branch/pointer relocation, all wrestler visual banks and wrestler-specific process logic.
- Full background header/palette object construction, fonts/text, fades and remaining frontend routines.
- Collision/ropes/turnbuckles, grapples, damage/pins/finishers, original CPU behavior and DCS audio backend.

Anything still missing stays absent or is reported in the generated frontiers. Harness code does not substitute for the game.

## N64 controls

The N64 layer maps controller state into portable arcade actions. Current bring-up mapping is:

| N64 | Portable action |
|---|---|
| Analog stick / D-pad | movement / frontend direction |
| A | run |
| C-Left | light punch |
| C-Up | power punch |
| C-Right | light kick |
| C-Down | power kick |
| R | block |
| Start | arcade attract/start input path |
| Z | N64-only debug HUD |

The final frontend/gameplay input behavior follows source routines as they are translated; the harness mapping is not treated as authoritative arcade behavior.

## Host verification

```sh
cmake -S . -B build-host -DCMAKE_BUILD_TYPE=Release
cmake --build build-host --parallel
ctest --test-dir build-host --output-on-failure
./build-host/wm_headless
```

The fix38 combat/ring/RNG/attract/hiscore host tests (`tests/arcade_port/fix38/`) verify themselves with plain `assert()`. Since `-DCMAKE_BUILD_TYPE=Release` above defines `NDEBUG`, which normally compiles every `assert()` to a no-op, their CMake targets force `-UNDEBUG` so those checks stay real under the documented build (confirmed by deliberately breaking one and watching it fail).

## N64 build

With libdragon configured:

```sh
export N64_INST=/path/to/n64_toolchain
make -j2
```

Output:

```text
wm_arcade_r9.z64
```

GitHub Actions fetches the historical WrestleMania source directly, regenerates translated tables/frontier reports and required artwork, builds the ROM, uploads the `wm-arcade-r9-build` Actions artifact, and publishes the ROM plus reports to the `rom-build` branch.

## Coverage

`port/translation_manifest.json` is canonical. CI regenerates `docs/PORT_COVERAGE.md` from it. `partial-source` means only the stated original subset is translated. `harness-only` means test/bring-up code that is forbidden from normal arcade execution.
