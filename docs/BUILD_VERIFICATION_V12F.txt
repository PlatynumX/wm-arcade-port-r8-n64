Fix39 V12f verification
=======================

Hardware symptom from V12e:
- second attract loop CPU read exception
- PC 0x800223C8
- exception address 0x0010001C
- backtrace: wm_fix39_attract_sprite_find -> fix39_attract_sprite -> fix39_render_hint
- backtrace main.c line delta 1317 - 1147 = 170, exactly matching renderer
  source delta line 179 (dynamic hint tip art lookup) - line 9
  (fix39_attract_sprite).

What that proves:
- the failing operation is the dynamic hint-art sprite-name lookup.
- the exception alone does not prove whether the invalid read came from the
  WmAttractHint input-name pointer or sprites[i].source_frame while scanning.

V12f correction:
- N64 hint renderer no longer dereferences WmAttractHint tip/mug/number strings.
- exact WHICH_HINT/WHICH_22_NUM art names are stored as inline char matrices.
- generated sprite finder scans an inline char-name/index table instead of
  dereferencing sprites[i].source_frame during lookup.
- returned WIMP sprite objects, pixels, metadata and palettes are unchanged.
- text, timing, source hint order and live scheduler are unchanged.
- tests/test_v12_patcher.py rejects both old pointer-bearing lookup paths and
  cross-checks the ten inline art triples against wmania_attract_data.c.
